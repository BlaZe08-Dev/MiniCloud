# MiniCloud v1.1.0 Release Notes

## Highlights
- **Real worker concurrency (V2-0):** workers execute up to `MINICLOUD_WORKER_SLOTS` (default 4) attempts in parallel instead of executing serially.
- **Round-robin uses real worker slots (V2-0b):** under the default `round_robin` policy, workers declaring concurrent execution receive jobs up to capacity (bounded at 8 live reservations per worker).
- **Byte-exact JSON payload delivery (SEC-067, V1x-02):** coordinator responses no longer HTML-escape `<`, `>`, or `&`, preventing payload corruption for valid payloads under 64 KiB.
- **Real version registration (V1x-03):** workers report their compiled version from `internal/version` rather than a static string.
- **Forward-only migration 000006:** adds `executes_concurrently` column to `workers` with additive-only `/v1` API extensions.

## Upgrade steps
1. **Database migration:** run the migrator binary (`migrate`) against PostgreSQL to apply migration `000006_worker_executes_concurrently.sql`. The migration is forward-only and non-destructive.
2. **Coordinator deployment:** restart or deploy the updated `coordinator` process.
3. **Worker deployment:** deploy updated `worker` processes.
   - Note: under the default `round_robin` policy, a worker only gets more than one slot if it declared `executes_concurrently: true` at registration (sent automatically by v1.1.0+ workers). Older workers (v1.0.0) that omit the field keep their existing single-slot behaviour.

## Rollback
MiniCloud provides three rollback options depending on operational requirements:

1. **Serial execution without code changes:** Start workers with `MINICLOUD_WORKER_SLOTS=1` (forces single-slot serial execution regardless of declared capacity), or run older worker binaries (such as v1.0.0).
2. **Dispatch policy rollback:** Set `MINICLOUD_DISPATCH_POLICY=fifo_pull` on the coordinator to switch from round-robin scheduling back to FIFO pull dispatch.
3. **Binary code rollback:** Revert coordinator and worker binaries to v1.0.0. Database migration `000006` is forward-only; the `executes_concurrently` column remains in the database and is safely ignored by previous coordinator code. The `/v1` API extensions are additive-only and backward compatible.

### Operator steps
- **Step 1:** To enforce serial execution immediately without code redeployments, configure `MINICLOUD_WORKER_SLOTS=1` across workers.
- **Step 2:** After a code rollback, if rolling forward again to v1.1.0+, run `UPDATE workers SET executes_concurrently = false;` against PostgreSQL before rolling forward (workers that are still running send `true` again on their next register), or restart all workers.

## Behaviour changes
- **Worker concurrency:** `MINICLOUD_WORKER_SLOTS` (default 4) runs up to that many attempts in parallel. The environment variable is bounded at worker startup to `[1, 1024]` (values exceeding 1024 fail fast with a configuration error).
- **Heartbeat & registration telemetry:** `available_slots` reports `total_slots` minus running attempts (previously always reported `total_slots`).
- **Round-robin concurrency:** under `round_robin`, concurrent workers are reserved work up to active attempts plus live reservations below `total_slots`, with a maximum of 8 live reservations per worker (`domain.MaxReservationsPerWorker`). Old workers keeping `executes_concurrently = false` remain restricted to one slot.
- **Panic resilience:** task execution panics and agent goroutine panics (in lease renewal, delivery budget, or heartbeat) are recovered cleanly without crashing the worker process. The affected slot is freed and the attempt transitions cleanly (retried or expired).
- **Bounded worker shutdown:** on signal cancellation, workers complete poll backoff (at most `MaxPollBackoff`, 3 s), drain running attempts up to `ResultDeliveryBudget` (60 s), and await the heartbeat routine.
- **JSON encoding & security header:** coordinator JSON responses via `writeJSON` no longer HTML-escape characters and include `X-Content-Type-Options: nosniff`.
- **Worker version telemetry:** workers register with compiled `internal/version.Version` (overrideable at build time via `-ldflags`).

## Known limits
- **Unauthenticated endpoints (SEC-004):** all HTTP coordinator and worker API endpoints remain unauthenticated, mitigated by the `127.0.0.1` bind default. Worker authentication and TLS are deferred to V3.
- **Single coordinator process (SEC-028):** MiniCloud runs a single coordinator daemon; distributed multi-coordinator coordination and consensus remain deferred.

## What is new but not part of the product runtime
- **Benchmark harness (`cmd/mcbench`):** standalone CLI tool and `make bench` target measuring throughput (S1), claim cost (S2), worker computation speed (S3), and burst drain (S4) against 127.0.0.1.
- **Benchmark baseline (`docs/benchmarks/`):** initial measurements recorded on a single development laptop, published as a baseline reference rather than a general performance claim.
- **Post-V1 design architecture (`docs/post-v1/`):** architectural design pack for future V2, V3, and V4 capabilities (ADR-0018); purely documentation and design freeze, with zero product runtime changes.
