## Findings

**F-R1, major, ADR-0017 note 16 / `internal/coordinator/sweeper.go` (`passGraceInput`), executed.** Pending grace has no time bound. While the sweeper has never succeeded, or every tick fails, every pass gets `GracePending: true` and no lapse is ever counted. A job whose chosen worker is fresh but never claims in time therefore never reaches `MAX_LAPSES`. The age arm stays closed because the pass works and the heartbeat is fresh. FS-19 ("bounded by L; then fallback") no longer holds. The ADR's grace windows last 30 s, but this suppression is unbounded.

The probe `audit_grace_test.go.txt` (log `audit-C-grace.log`) runs 20 windows (100 s), with grace windows set to 0:

```
mode=control            assignment_lapses=3 uncounted_lapse_events=0  heartbeat_stale=false fallback_claim_by_other_worker=true
mode=never-ticked       assignment_lapses=0 uncounted_lapse_events=20 heartbeat_stale=false fallback_claim_by_other_worker=false
mode=fail-always        assignment_lapses=0 uncounted_lapse_events=20 heartbeat_stale=false fallback_claim_by_other_worker=false
mode=first-ok-then-fail assignment_lapses=0 uncounted_lapse_events=20 heartbeat_stale=false fallback_claim_by_other_worker=false
```

Trigger: `SweepExpiredLeases` fails persistently while `Now` and the pass succeed, or a sweeper is built and never run. One `JOB_ASSIGNMENT_LAPSED` row is written per window for as long as this lasts.

Suggested fix (orchestrator decides): bound the pending state on the repository clock, for example to the outage window counted from the last successful tick or from the sweeper's construction. Then pin it with a test like the probe.

**F-R2, minor, `internal/coordinator/sweeper.go`, executed.** Note 16's "after a failed tick" part has no test. Mutant A05 removes the pending publish after a failed sweep and survives the whole coordinator and cmd suites. `TestCoordinator_AssignmentLoop_GracePendingUntilFirstSweep` covers only the first tick.

**F-R3, minor, `internal/coordinator/service.go`, executed.** The submit-coalescing guard has no test: mutant A04 (trigger buffer 64) survives. The rule it guards is note 19: "a burst of submits adds at most one round".

**F-R4, minor, `internal/coordinator/assignment_loop.go`, executed.** The A2 window is not pinned to one minute. Mutant A03 (50 s) survives, because 181 rounds at 1 s give 4 lines under both values.

**F-R5, minor, `internal/coordinator/assignment_loop.go`, executed.** The production yield (`sleepContext`) is never exercised: mutant A02 (no wait) survives. Every yield test injects `SetYieldForTest`. INV-20's release of `s.mu` is pinned (D06, D07); the wait of `MIN_YIELD` is not.
