### F-P0-03-1 (major) Quickstart job ID cannot work as written
README lines 133 and 153: `./bin/mc get job_1_9fb43b921313` and `./bin/mc attempts job_1_9fb43b921313`. The ID is generated randomly per submit and the README never says to substitute it.
Evidence (executed, ev 03): literal run gave `Query failed (HTTP 404): {"error":{"code":"JOB_NOT_FOUND",...}}` rc=1 for both commands. The real ID from my submit was `job_1_ea776f9a0bbd`. Also (executed, ev 22) running `get` immediately after `submit` shows `State: QUEUED` and `Attempt ID:` empty, and `attempts` shows `0 total`; the README says "Query the completed job" with no wait.
Replacement for the text before line 130:
```
Copy the `ID:` value from the submit output; the job ID is generated per submission and yours will differ from the one shown below. Wait about a second for the worker to pick the job up, then query it (repeat if `State` is still `QUEUED` or `RUNNING`):
```
Replace each literal ID in the commands with `<job_id>` (for example `./bin/mc get <job_id>`), keep the sample outputs, and add one sentence: "The IDs, attempt IDs and times in the outputs below come from one sample run."

### F-P0-03-4 (major) Cancellation is described as cooperative and working; it does not reach the worker
README line 263: "Request cooperative cancellation of a job. Returns HTTP 200."; also line 328 lists "cooperative cancellation" in V1 without saying it is not built.

Only cancel of QUEUED jobs takes effect today (code, `internal/storage/inmemory.go:742`).
Replacement for line 263: "- `POST /v1/jobs/{id}/cancel` - Request cancellation. Note for the orchestrator: a cancel request on a running job ending in `SUCCEEDED` is the already-known 4d gap, not a new SEC finding; I did not file one.

### F-P0-03-7 (major) Testing section warns about the container but not about the commands that trigger it, and does not point to the safe path
README lines 306-322.
Evidence: code, ev 15/16: `tests/integration/postgres_wiring_test.go:109-121` runs `docker compose ... stop postgres` / `start postgres`, called from `TestPostgresWiring_DatabaseOutageAndRecovery`, and from `TestSecurity_PartD_Outage_MidDispatchAndMidCommit` and `TestSecurity_PartD_LeakScan` in `part_d_security_test.go` (ev 16, helper callers). These run whenever `MINICLOUD_TEST_DATABASE_URL` is set in the environment during `go test ./...`, which includes `make test` and `make test-race` (ev 18 Makefile: plain `go test -v ./...`). The README's warning (line 322) names two files and says the container stops temporarily, but never says (a) that `make test`, `make test-race` and `go test ./...` trigger it when the variable is exported, (b) that the container is shared, so other worktrees' runs fail while it is down, (c) that `make test-db` is the safe command (it runs only `./internal/storage/postgres/...`), (d) that the unset-URL form skips these tests. The `_test` rule is explained (line 321, true: `internal/storage/postgres/testhelper_test.go:34`, `tests/integration/postgres_wiring_test.go:42`), but "ends in `_test`" alone does not say that `.env.example` points the test URL at the shared `minicloud_test`.
Replacement for line 322:
```
- **Container interruption warning:** With `MINICLOUD_TEST_DATABASE_URL` set in your environment, `go test ./...` (and therefore `make test` and `make test-race`) runs outage tests (`tests/integration/postgres_wiring_test.go`, `tests/integration/part_d_security_test.go`) that run `docker compose stop postgres` and `start postgres` on the shared `minicloud-postgres` container. Anything else using that database is disconnected meanwhile. For database tests use `make test-db`, which reads the URL from `.env` and runs only `internal/storage/postgres`. To run everything else, unset the variable: `env -u MINICLOUD_TEST_DATABASE_URL go test ./...`. Database tests skip when it is unset; a skipped test is not a passed test.
```
Also reword line 316 `make db-reset-test` to "Drops and recreates the shared `minicloud_test` database (the name is hardcoded, so it does not touch other databases)" and add to `make db-down` "stops the shared container; every dependent test run loses its database". Both are code-confirmed (Makefile `db-reset-test`, `db-down`).
