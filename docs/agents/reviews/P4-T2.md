## 1. Executive Summary

Task P4-T2 scopes the citation integrity checker (`tests/docs/citations_test.go`) so that frozen historical review records located under the reviews directory do not fail Rule A on quoted repo-relative markdown link targets (such as README links quoted from earlier PR revisions or ADR placeholder links).

The implementation was audited by an independent Auditor in a clean clone (`/tmp/audit-t2`) over HTTPS with no `.env` and `MINICLOUD_TEST_DATABASE_URL` unset.

Key audit findings:
1. **Rule Logic & Scoping Precision**: Only the markdown link target loop within `CheckRuleA` is skipped when `IsFrozenReviewRecord` returns true. All other rules (Rule A code-span paths, Rule B line anchors, Rule C test names, Rule D forbidden strings, Rule E ADR numbers, and Rule F allowlist staleness) continue to execute on review records.
2. **Live Documents Unweakened**: For any path where `IsFrozenReviewRecord` returns false, `CheckRuleA` executes the exact same code branches as `origin/main`.
3. **Robust Bypass Resistance**: All adversarial probe attempts (path traversal, symlinks to live files, symlinked directories, lookalike prefixes, case variations, trailing/double slashes, backslashes, absolute paths, and root doc probes) were blocked.
4. **Allowlist Integrity**: `tests/docs/citation_allowlist.txt` is byte-identical to `origin/main` (SHA-256 hash verified).
5. **Real Records Proof**: With the four real P0-03 review records present, `origin/main` fails Rule A 7 times (2 in round 2, 5 in round 3), whereas `P4-T2` passes with zero failures.
6. **Mutation Proofs Verified**: All mutations (scoping removal, scope widening, prefix matching without trailing slash, and symlink guard removal) were reproduced in a throwaway copy and failed the expected unit tests.

One informational provisional finding (`FIND-PROV-P4T2-01`) is recorded: because markdown link targets are skipped unconditionally for frozen records, broken file-relative links within review records are not flagged. This is an accepted and documented design trade-off to avoid allowlist inflation.

### Question 3: Real Problem Scoping Impact Analysis
**Evidence label:** executed (logged in `docs/agents/reviews/P4-T2-evidence.txt`).

1. **Does scoping hide any real problem in review records?**
   - **Yes (for link targets):** If a review record contains a broken markdown link target that is intended to be a local relative path (for example, a link to a nonexistent local evidence file), Rule A does not report it because the entire link target loop is skipped when `frozen == true`.
   - **No (for code spans, line anchors, test IDs, ADRs, forbidden strings):**
     - Code spans: `CheckRuleA` loop 2 still executes; missing code span paths fail Rule A.
     - Rule B: Line anchors continue to be checked if the target file exists.
     - Rule C: Scans review records for test identifiers; nonexistent test names fail Rule C.
     - Rule D: Scans review records for forbidden strings; presence of forbidden URL schemes or prefixes fails Rule D.
     - Rule E: Scans review records for ADR numbers; nonexistent ADR numbers fail Rule E.
     - Rule F: Scans review records for allowlist usage; stale entries are detected.
2. **Demonstration:**
   - In scratch probes, a broken relative link to a nonexistent companion evidence file inside a review record was skipped silently by Rule A without error.
   - In contrast, citing a missing code span path was caught by Rule A, citing an invented nonexistent test was caught by Rule C, forbidden strings were caught by Rule D, and a nonexistent ADR number was caught by Rule E.

### Question 8: Builder Handoff Verification & Orchestrator Decisions
**Evidence label:** confirmed by code reading and executed.

Every claim in `docs/agents/handoffs/P4-T2.md` was reproduced and verified against the implementation.

Review of Builder's Decisions for the Orchestrator:
1. **Rule A link targets skipped vs re-resolved:**
   *Auditor's opinion:* Skipping markdown link targets inside the reviews directory is the correct and only viable solution. As demonstrated, review records quote draft paths (such as placeholder ADR citations) that never existed in the repository. Re-resolving root-relative links would still leave those citations broken, requiring new allowlist entries and violating the invariant against allowlist growth. Retaining code-span, ADR, line anchor, and test identifier rules provides adequate guardrails for review documents.
2. **Symlink handling (any symlink in path forces live document status):**
   *Auditor's opinion:* Strongly endorse. This provides defensive containment against symlink directory tricks or attempts to disguise live documentation inside the reviews folder.
3. **Real records import in separate task:**
   *Auditor's opinion:* Agree. File ownership rules in `TASKS.md` dictate that importing review files belongs to the designated doc/follow-up task.

## 5. Attacks Attempted That Did NOT Find Issues

5. **Case normalization tricks:** Tested case variations of the review directory path. Case sensitivity prevented scope match.
6. **Separator manipulations:** Tested trailing slashes, bare directories, backslashes, absolute paths, and double slashes. None bypassed the clean path and prefix requirements.
7. **Cross-directory lookalikes:** Placed a file named like a review record outside the review folder. Handled as live document and failed Rule A.
8. **Root documents integrity:** Verified that broken links in `README.md`, `CHANGELOG.md`, `GEMINI.md`, and `AGENTS.md` continue to fail Rule A.
9. **Code-span forgery in review records:** Verified that citing nonexistent repo paths in code spans inside a review record continues to fail Rule A.
10. **Test name falsification:** Verified that citing nonexistent tests in review records continues to fail Rule C unless exempt words are present.
11. **Forbidden string insertion:** Verified that adding forbidden URL schemes or prefixes in review records continues to fail Rule D.
12. **ADR number forgery:** Verified that citing nonexistent ADRs in review records continues to fail Rule E.
