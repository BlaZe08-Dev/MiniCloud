## Attacks Attempted That Did NOT Find Issues

- **Attack 1 (Before/After real binaries on own DB):** Built coordinator and worker from `origin/main` (28f5c61) and branch (`95980ba`). Submitted 65,000-byte payloads with `<`, `>`, `&`, U+2028, U+2029, and mixed strings. On `origin/main`, all failed `PERMANENT` because the worker saw payload size > 64 KiB. On the branch, all succeeded on attempt 1. Boundary testing confirmed `origin/main` maxes out at 10,920 `<` characters, whereas branch accepts up to exact 65,536 bytes and returns HTTP 413 `PAYLOAD_TOO_LARGE` at 65,537 bytes.
- **Attack 2 (Headers audit):** Queried all endpoints on real running coordinator. Every response written via `writeJSON` carries `Content-Type: application/json` and `X-Content-Type-Options: nosniff`. Standard library mux 404/405 error responses carry `text/plain` and also include `nosniff`.
- **Attack 3 (JSON equivalence):** Sent identical requests to `origin/main` and branch builds. Decoded response JSON structures showed identical values. Raw wire bytes differed strictly by unescaped `<`, `>`, `&`.
- **Attack 4 (Wire byte consumers):** Grepped repository for raw escape dependencies; none found. Tested `mc get` and `mc list` on both builds with jobs containing `<`, `>`, `&`; CLI sanitization (SEC-048) remained identical.
- **Attack 5 (Worker limits & wire sizing):** Sized 65,536-byte payload plus envelope at 65,855 bytes on wire, utilizing only 14.4% of `MaxPollResponseBytes` (458,752 bytes). Tested payloads full of escaped `\"` and `\\`; raw size remains <= 65,536 bytes and envelope overhead remains 319 bytes.
- **Attack 6 (U+2028 / U+2029 verification):** Confirmed with standalone Go program that `json.Encoder` with `SetEscapeHTML(false)` leaves U+2028/U+2029 raw inside `json.RawMessage` while still escaping them in plain string values. Verified docs accurately report this distinction.
- **Attack 7 (Mutant tests & race stability):** Re-tested mutants a, b, c, and added mutants d and e. All mutants are reliably killed. Running the 5 regression tests (`TestAPI_PollPayloadIsNotHTMLEscaped`, `TestAPI_PollPayloadMaxSizeBoundary`, `TestAPI_NosniffHeaderOnEveryWriteJSONResponse`, `TestAPI_ResponseWireChangeIsJSONEquivalent`, `TestAPI_ErrorBodyIsNotHTMLEscaped`) under `-race -count=50` passed with 0 data races.
- **Attack 8 (Scope and docs):** `git diff --name-only origin/main...origin/agent/claude/V1x-02` strictly touches `internal/api/escape_test.go`, `internal/api/handlers.go`, and documentation/handoffs. All claims in `CHANGELOG.md`, `docs/PROJECT_STATE.md`, `docs/agents/TASKS.md`, `docs/security/field-limits.md`, and `docs/security/findings.md` accurately reflect code behavior.
- **Attack 9 (Unlisted encoders and error paths):** Audited `internal/api` for any other JSON encoders or manual string formatting. Found none; `writeJSON` is universally used. Recovery middleware handles panics via `writeError`, preserving `nosniff`.
