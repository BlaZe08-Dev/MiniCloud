## Design decisions and deviations (with reasons)

- **D1 Backoff is a parameter of the sweep (answers Q-4b-1: yes, 4b owns it).** `SweepParams.Backoff` is a `domain.BackoffFunc` supplied by the caller (`policy.BackoffFunc(rnd)`). Repositories contain no randomness. A nil `Backoff` is rejected with `ErrInvalidRequest` and mutates nothing (no hidden default randomness).
- **D2 Cap applies before jitter.** ADR-0015 writes `min(30 s, 1 s * 2^(n-1)) * jitter`; I implemented exactly that, so the longest delay is 45 s. If "cap 30 s" was meant to bound the final delay, `ComputeBackoff` changes in one place and `TestDomain_ComputeBackoff_FullJitter` rows change (Q-3).
- **D3 Grace input shape.** `SweepGraceState{StartupGraceUntil, OutageWindowUntil, CooldownUntil}`, absolute instants compared with the repository clock inside the locks. Reading chosen: suppressed if `now < StartupGraceUntil`; else not suppressed if `now < CooldownUntil` ("reaping proceeds during cooldown"); else suppressed if `now < OutageWindowUntil`. The zero value suppresses nothing (a caller that forgets grace reaps; see security S3). Q-1 and Q-2.
- **D4 `RenewLease` records no event.** `docs/state-machine.md` section 5 lists `LEASE_RENEWED`, but neither ADR-0014, protocol 6.1 nor the plan's 4b scope asks the repository to write it, and one row per renewal every 10 s per attempt is unbounded audit growth. Pinned by `TestConformance_RenewLease_AcceptUntilSwept` (event count unchanged). Q-4.
- **D5 Renewal evaluation order mirrors commit** (protocol 6.3): terminal job, then LOST attempt of this job (`ErrLeaseExpired`), then superseded / not RUNNING / wrong token / unknown attempt id (`ErrStaleAttempt`), then wrong worker (`ErrWorkerMismatch`). Two consequences: an unknown attempt id is 409 `STALE_ATTEMPT_REJECTED`, not 404 `ATTEMPT_NOT_FOUND` (the protocol table lists stale at priority 3 and not-found at 6; commit has always behaved this way); and a rejected renewal writes nothing (no diagnostic event, no attempt closure; the sweeper closes it later). Q-5.
- **D6 LOST is evaluated before token mismatch** (ADR order): a caller who knows a job id and an attempt id, with no token, can distinguish "swept" (409 `LEASE_EXPIRED`) from "stale". On a commit it also writes the one bounded diagnostic. Same class as SEC-024; see security F-4b-1.

## 2. Job States

| State | Classification | Meaning | Allowed Next States |
|---|---|---|---|
| `SUBMITTED` | Ephemeral / Initial | Job has passed schema validation and been recorded by the API. | `QUEUED`, `REJECTED` |
| `QUEUED` | Active / Pending | Job is waiting in the scheduling pool for an eligible worker. | `RUNNING`, `CANCELLED` |
| `RUNNING` | Active / In-Flight | An attempt has been dispatched and accepted by a worker under a lease. | `SUCCEEDED`, `RETRYING`, `FAILED`, `CANCEL_REQUESTED` |
| `CANCEL_REQUESTED` | Active / Draining | Cancellation was requested while an attempt was running; awaiting the worker's commit or lease expiry. | `CANCELLED`, `SUCCEEDED`, `FAILED` |
| `RETRYING` | Active / Backoff | An attempt failed or timed out, and the job is waiting out exponential backoff before becoming eligible for re-dispatch. | `RUNNING`, `FAILED`, `CANCELLED` |
| `SUCCEEDED` | **Terminal** | A valid attempt result has been committed to durable storage. | *None* |
| `FAILED` | **Terminal** | Execution failed permanently, or maximum attempt budget was exhausted. | *None* |
| `CANCELLED` | **Terminal** | Job was cancelled before execution started, or running attempt confirmed cooperative cancellation / expired. | *None* |
| `REJECTED` | **Terminal** | Job submission was rejected before acceptance (e.g., unsupported task type, invalid payload bounds). | *None* |

### SEC-012: Worker Execution Timeout Not Clamped Above
- **Status**: Informational, Open (inferred from code review, unconfirmed).
- **Detail**: `internal/worker/client.go:267-270` directly converts `assignment.TimeoutSeconds` into a `time.Duration` without an upper bound clamp. If a compromised coordinator provides an enormous timeout, worker execution context will remain held until process termination.
- **Verification Step**: `TestWorker_ExcessiveTimeoutClamped` (future test returning a 24-hour timeout from coordinator asserting worker clamps execution context to maximum threshold).

### SEC-013: Monotonic Sequence Counter Exposed in Job and Attempt IDs
- **Status**: Informational, Open (inferred from code review, unconfirmed).
- **Detail**: `internal/coordinator/service.go` func `generateID` constructs IDs using `fmt.Sprintf("%s_%d_%s", prefix, seq, hex.EncodeToString(b))`. While the 48 bits of randomness prevent brute-force guessing, the sequence counter leaks total job submission volume since coordinator boot.
- **Verification Step**: `TestCoordinator_IDLeakage` (future test asserting whether sequential counters are exposed or replaced with opaque cryptographically random identifiers).

### SEC-015: Unbounded total_slots Upper Bound in Worker Registration
- **Status**: Low, Confirmed, Fixed (Slice 3d).
- **Detail**: In `POST /v1/workers/register` (`internal/coordinator/service.go` func `RegisterWorker`), `worker.TotalSlots` is validated to ensure it falls within `[1, 1024]`. Requests with `total_slots < 1` or `total_slots > 1024` return HTTP 400 `INVALID_REQUEST`. As defense-in-depth, PostgreSQL migration 000003 enforces `chk_workers_total_slots_range CHECK (total_slots >= 1 AND total_slots <= 1024)`.

		return nil, fmt.Errorf("MINICLOUD_HEARTBEAT_INTERVAL must be positive")
	}
	if cfg.WorkerTimeout <= 0 {
		return nil, fmt.Errorf("MINICLOUD_WORKER_TIMEOUT must be positive")
	}
	if cfg.WorkerTimeout < 3*cfg.HeartbeatInterval {
		return nil, fmt.Errorf("MINICLOUD_WORKER_TIMEOUT (%v) must be at least 3x MINICLOUD_HEARTBEAT_INTERVAL (%v)", cfg.WorkerTimeout, cfg.HeartbeatInterval)
	}
	if cfg.ReaperInterval <= 0 {
		return nil, fmt.Errorf("MINICLOUD_REAPER_INTERVAL must be positive")
	}
	if cfg.ReaperInterval > cfg.WorkerTimeout {
		return nil, fmt.Errorf("MINICLOUD_REAPER_INTERVAL (%v) must not exceed MINICLOUD_WORKER_TIMEOUT (%v)", cfg.ReaperInterval, cfg.WorkerTimeout)
	}
	if cfg.DefaultMaxAttempts <= 0 {
		return nil, fmt.Errorf("MINICLOUD_DEFAULT_MAX_ATTEMPTS must be positive")
	}
	if cfg.MaxJobRuntime <= 0 {
		return nil, fmt.Errorf("MINICLOUD_MAX_JOB_RUNTIME must be positive")
	}
	if cfg.StorageDriver != "memory" && cfg.StorageDriver != "postgres" {
		return nil, fmt.Errorf("MINICLOUD_STORAGE_DRIVER must be either 'memory' or 'postgres' (got %q)", cfg.StorageDriver)
	}
	if cfg.StorageDriver == "postgres" && cfg.DatabaseURL == "" {
		return nil, fmt.Errorf("MINICLOUD_DATABASE_URL cannot be empty when storage driver is 'postgres'")
	}
	if cfg.DBMaxConns <= 0 {
		return nil, fmt.Errorf("MINICLOUD_DB_MAX_CONNS must be positive")
	}
	if cfg.DBMinConns < 0 {
		return nil, fmt.Errorf("MINICLOUD_DB_MIN_CONNS cannot be negative")
	}
	if cfg.DBMinConns > cfg.DBMaxConns {
		return nil, fmt.Errorf("MINICLOUD_DB_MIN_CONNS (%d) must not exceed MINICLOUD_DB_MAX_CONNS (%d)", cfg.DBMinConns, cfg.DBMaxConns)
	}
	if cfg.DBQueryTimeout <= 0 {
		return nil, fmt.Errorf("MINICLOUD_DB_QUERY_TIMEOUT must be positive")
	}

	return cfg, nil
}

// LoadWorkerConfig loads and validates worker configuration from environment variables.
func LoadWorkerConfig() (*WorkerConfig, error) {
	cfg := &WorkerConfig{
		WorkerID:          getEnv("MINICLOUD_WORKER_ID", ""),
		CoordinatorURL:    getEnv("MINICLOUD_COORDINATOR_URL", "http://127.0.0.1:8080"),
		TotalSlots:        getIntEnv("MINICLOUD_WORKER_SLOTS", 4),
		HeartbeatInterval: getDurationEnv("MINICLOUD_HEARTBEAT_INTERVAL", 2*time.Second),
		LogLevel:          getEnv("MINICLOUD_LOG_LEVEL", "info"),
	}

	if cfg.CoordinatorURL == "" {
		return nil, fmt.Errorf("MINICLOUD_COORDINATOR_URL cannot be empty")
	}
	if cfg.TotalSlots <= 0 {
		return nil, fmt.Errorf("MINICLOUD_WORKER_SLOTS must be positive, got %d", cfg.TotalSlots)
	}
	if cfg.HeartbeatInterval <= 0 {
		return nil, fmt.Errorf("MINICLOUD_HEARTBEAT_INTERVAL must be positive")
	}

	return cfg, nil
}

func getEnv(key, defaultVal string) string {
	if val, exists := os.LookupEnv(key); exists {
		return val
	}
	return defaultVal
}

func getIntEnv(key string, defaultVal int) int {
	valStr := os.Getenv(key)
	if valStr == "" {
		return defaultVal
	}
	val, err := strconv.Atoi(valStr)
	if err != nil {
		return defaultVal
	}
	return val
}

func getDurationEnv(key string, defaultVal time.Duration) time.Duration {
	valStr := os.Getenv(key)
	if valStr == "" {
		return defaultVal
	}
	val, err := time.ParseDuration(valStr)
	if err != nil {
		return defaultVal
	}
	return val
}

 ## Roadmap
 
 MiniCloud development follows a three-version roadmap defined in [docs/roadmap.md](docs/roadmap.md):
 
-- **V1 (Phases 0–4):** Core execution with allowlisted tasks, transactional FIFO pull dispatch (`fifo_pull`), PostgreSQL durability, lease management, bounded retries, cooperative cancellation, and post-Phase 4 assignment-based round-robin scheduling.

 - **V2 (Phase 6 & Transport Evaluation):** Resource-aware scheduling policies, comparative benchmark generator, fault injection harness, and Redis Streams dispatch evaluation against the PostgreSQL baseline (ADR-0006). PostgreSQL remains the durable source of truth.
 - **V3 (Docker Isolation & Multi-Machine):** Docker container task isolation behind the executor interface (ADR-0005), worker mutual TLS (mTLS), worker API token authentication, and multi-machine deployment hardening.
