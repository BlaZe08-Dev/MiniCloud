## 2. Checks

### Item 1: rule against code (confirmed by code reading, plus the executed checks named)
- Domain: `CanReserve` = `active+reserved < assignable && reserved < MaxReservationsPerWorker`; `HasFallbackRoom` = the sum without the cap; `AssignableSlots(false, n) = 1` (`internal/domain/assignment.go`).
- In memory: `eligibleWorkersLocked` calls `CanReserve` per decision under `r.mu`, with `liveReservationsLocked` counting only `AssignmentExpiresAt.After(now)`; the fallback arms call `HasFallbackRoom` with the same count and return `ErrWorkerNoCapacity` (`internal/storage/inmemory_assignment.go`).
- PostgreSQL snapshot (`assignment.go:395-399`) and re-check (`:484-488`): the same text; the re-check runs as a new statement after `SELECT ... FOR UPDATE` on the worker row in a released savepoint, so it gets a fresh READ COMMITTED snapshot and the row lock stays until the pass commits. `claimTx` re-reads `executes_concurrently` under the worker lock and applies `HasFallbackRoom` to fallback claims only.
- Paths: own arm turns R into A (claim clears the assignment columns, `assignment.go:719-722`), sum unchanged, still bounded by `total_slots - A > 0`. Lapse and age arms: `A + R < S` under the worker lock. Re-register lowering S: no new reservation while `A + R >= S`; executed in `abuse/attacks.txt` A2, 15 monitor samples with `A + R > S`, all with `S = 1` right after a re-register to 1 slot or without the field, none after. Concurrent claim and pass: lock order jobs then workers on both sides; mutant M8a killed. Expired but unrevoked: not counted (M5, M5pg killed); in the abuse run 8 reservations lapsed and new ones were made only while the worker polled.
- No path found where `R > 8`: reservations are created only by the pass, which checks `R < M` in the snapshot and in the re-check. Executed: 5471 monitor samples, `samples with R > 8` empty.
