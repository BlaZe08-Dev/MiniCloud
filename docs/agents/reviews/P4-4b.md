## 1. Executive Summary

Slice P4-4b delivers the core storage and domain mechanisms for Phase 4:
1. Pure exponential retry backoff with full jitter (`internal/domain/retry.go`).
2. Sweeper domain types and grace representation (`internal/domain/sweep.go`).
3. Database migration `000004_leases_retries_cancellation.sql` adding `lease_expires_at`, `error_class`, `last_error`, `not_before`, `cancel_requested_at`, indexes, and check constraints (`docs/schema.md`).
4. In-memory and PostgreSQL `RenewLease` implementing the symmetric accept-until-swept rule and cooperative cancellation delivery (ADR-0014, ADR-0016).
5. In-memory and PostgreSQL `SweepExpiredLeases` under canonical lock ordering (`jobs -> workers -> attempts`), in-lock correctness re-check, in-lock grace check, and state resolution (ADR-0014, ADR-0015).
6. Commit conflict evaluation order: terminal job (`JOB_ALREADY_TERMINAL`) > swept attempt (`LEASE_EXPIRED`) > stale/superseded attempt (`STALE_ATTEMPT_REJECTED`), with unauthenticated diagnostic growth bounded to 1 per attempt via partial unique index.
7. Minimal HTTP mapping in `internal/api/handlers.go` (`ErrLeaseExpired` -> 409 `LEASE_EXPIRED`).

The implementation is sound, robust, and rigorously tested. All gates were reproduced with exact count matches. One owner-decision deviation regarding the in-lock cooldown grace check was identified via break-before-fix proof and documented as Finding F-4b-A1 with an exact fix.

## 4. Existing Tests Changed

Two pre-existing test files were modified by the builder. Both were examined in full:
1. `internal/storage/storagetest/conformance.go` (`RunCommitAttemptNonRunningAttemptConformance`):
   - **Diff**: The loop over states previously checked `COMPLETED, FAILED, LOST`. The builder changed it to `COMPLETED, FAILED, CANCELLED, TIMED_OUT`.
   - **Evaluation**: In Slice 4a, attempting to commit on a `LOST` attempt returned `ErrStaleAttempt`. In Slice 4b, per ADR-0014 and Protocol 6.3 priority 2, committing on a `LOST` attempt must return `ErrLeaseExpired` (`LEASE_EXPIRED`). The builder moved the `LOST` test case to `RunCommitAttemptConflictOrderConformance` (where it explicitly asserts `ErrLeaseExpired`), and added `CANCELLED` and `TIMED_OUT` to `RunCommitAttemptNonRunningAttemptConformance`. No assertion was weakened.
2. `internal/storage/postgres/migrator_test.go` (`TestSchemaInvariants_SQLViolations`):
   - **Diff**: Eight raw `INSERT INTO attempts` statements were updated to supply `lease_expires_at, CURRENT_TIMESTAMP + INTERVAL '30 seconds'`.
   - **Evaluation**: Migration `000004` implements `ALTER TABLE attempts ALTER COLUMN lease_expires_at DROP DEFAULT;` as mandated by `docs/schema.md` section 5. Because the default was dropped, subsequent raw SQL inserts without `lease_expires_at` fail on PostgreSQL `NOT NULL` constraint (`23502`) before reaching the target check/unique constraints under test. Adding `lease_expires_at` allows the test to reach and validate the exact intended invariants (unique active attempt, distinct attempt numbers, bounded output size, valid states). No assertion was weakened.

## 5. Break Before Fix & Conformance Verification

In a dedicated throwaway worktree (`~/mc-mut-gemini`), independent audit tests were executed across all mandated areas:

### (a) Migration 000004
- **Database at 000003 with existing rows**: Verified via `TestMigrator_Migration000004_UpgradeFrom000003_WithExistingRows`. - **Fail-loud on pre-existing duplicate diagnostics**: Verified via `TestMigrator_Migration000004_PreExistingDuplicateDiagnostic_FailsLoudly`. Building `idx_job_events_unique_diagnostic_late_result` over duplicate audit rows fails atomically and rolls back without deleting audit rows.

### (b) RenewLease Semantics
- Verified on both in-memory and PostgreSQL backends via the throwaway conformance probe (see `docs/agents/reviews/P4-4b-evidence.txt` section 8):
  - Terminal job (`CANCELLED` / `SUCCEEDED` / `FAILED`): returns `ErrJobAlreadyTerminal`.
  - `CANCEL_REQUESTED` job: returns `CancelRequested: true` and current expiry without extending `lease_expires_at`.
  - Swept (`LOST`) attempt: returns `ErrLeaseExpired`, never resurrects the attempt.
  - Wrong attempt ID / unknown attempt: returns `ErrStaleAttempt`.
  - Wrong worker ID: returns `ErrWorkerMismatch`.

### (c) SweepExpiredLeases Semantics
- **Lock order**: Verified via `TestPostgresRepository_Sweeper_CanonicalLockOrder`. Probing with `NOWAIT` confirms canonical order `jobs SKIP LOCKED -> workers FOR UPDATE -> attempts FOR UPDATE`.
- **Skipped candidate**: Lock timeout or `SKIP LOCKED` skip returns `SkippedLocked` and `nil` error (not a failed tick).
- **Terminal jobs**: `RUNNING` attempts under `SUCCEEDED`/`FAILED` jobs are closed as `LOST` (with `error_class = LEASE_EXPIRED`), attempts under `CANCELLED` jobs closed as `CANCELLED` (no class); job states and `updated_at` remain untouched.
- **Attempt consumption & retries**: `LOST` attempts consume `max_attempts`. When `attempt_no < max_attempts`, job transitions to `RETRYING` with `not_before` calculated via backoff; when `attempt_no >= max_attempts`, job transitions to `FAILED`.
- **Cancel requested**: Expired attempt on `CANCEL_REQUESTED` job transitions to `CANCELLED` and writes only `JOB_CANCELLED` with `resolved_by: lease_sweeper`.
- **In-lock grace check**: The throwaway audit probe for cooldown grace confirmed that Claude's implementation of `SweepGraceState.Suppresses` allows lease expiry while `CooldownUntil` is active, violating the owner decision (Finding F-4b-A1).

### (d) CommitAttempt 409 Order & Diagnostic Limit
- Verified on both backends:
  - Priority 1 (terminal job) beats Priority 2 (swept attempt): returns `ErrJobAlreadyTerminal`.
  - Priority 2 (swept attempt) beats Priority 3 (token mismatch / supersession): returns `ErrLeaseExpired` even when an invalid token is provided.
  - Concurrent late commits: 10 concurrent commits on a swept attempt record exactly 1 `DIAGNOSTIC_LATE_RESULT` event (arbitrated by the partial unique index in Postgres and in-memory map lock).

### (e) ComputeBackoff Edge Cases
- Verified via the throwaway audit probe for backoff edge cases in `internal/domain`:
  - `attemptNo <= 0` treated as attempt 1.
  - `attemptNo` values 0, 1, 31, 32, 64, 1000 all bounded by `[BaseBackoff * 0.5, MaxBackoff * 1.5]` = `[0.5s, 45s]`.
  - No integer overflow or panics.
  - Random source clamping `[0.0, 1.0]` and deterministic reproducibility verified.

## 7. Security Review & Builder Findings Evaluation

- **F-4b-1 (Informational, within SEC-004)**: Evaluated and **confirmed**. Because `LOST` is evaluated at Priority 2 before `lease_token` validation at Priority 3, an unauthenticated caller knowing only `(job_id, attempt_id)` can query whether an attempt was swept to `LOST` and trigger one diagnostic event.
- **F-4b-2 (Low)**: Evaluated and **confirmed**. In `internal/storage/postgres/repository.go` func `DispatchJob` and func `DispatchNextJob`, attempt IDs are generated as `fmt.Sprintf("att_%s_%d", jobID, nextAttemptNo)`. Since attempt numbers start at 1, attempt IDs are trivially derivable from the `job_id`.
- **F-4b-3 (Low)**: Evaluated and **confirmed**. In `internal/storage/postgres/leases.go` func `applySweep` and `internal/storage/inmemory.go` func `sweepAttemptLocked`, the `default:` branch returns `nil, nil` for jobs in `QUEUED`, `SUBMITTED`, or `RETRYING`. The sweeper rolls back and counts `SkippedChanged`, leaving the attempt `RUNNING` and permanently occupying a worker capacity slot.
- **F-4b-4 (Informational)**: Evaluated and **confirmed**. `TestPostgresRepository_Concurrency_MixedOperationsStress` samples very few sweeps (3 in 20 runs). Concurrency safety is properly established by the dedicated race test `TestPostgresRepository_Concurrency_SweeperRenewCommitCancelRace`.
