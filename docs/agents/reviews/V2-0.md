## 3. Attack list

### 1. Slot accounting (executed)
Attack tests in `audit_v20_test.go.txt`, run on unmodified `7273571` with `-race` (`audit-tests-v20.log`, rc=0, all PASS):
- Panic in `Validate`: `Audit_PanicInValidateReleasesSlot` PASS. Slot released once, worker polls again, running 0, no result, log carries `panic_type=string` and not the payload.
- Panic in one attempt next to a running one: `Audit_PanicDoesNotKillConcurrentAttempt` PASS (j1 not cancelled, delivers; j2 no result).
- Result delivery failing forever (HTTP 500): `Audit_DeliveryFailingHoldsSlotUntilBudget` PASS, "slot released after 1m0s of fake time and 26 failed deliveries"; no poll before the budget elapsed.
- 409 / 403 / recognised 404 / `cancel_requested` on renew at the moment of completion: `Audit_RenewVerdictRacesCompletion`, 11 sub-cases x 50 iterations, PASS. Orders: race (409: 50 of 50 result first; 403 and 404: 2 of 50 verdict first), verdict first (0 result requests for lost verdicts, 1 for cancel, 50 of 50), verdict during a held result request (1 result request then "lease lost while delivering; dropping the result", 50 of 50). Every iteration: running back to 0, available 1, at most one result, no invariant breach.
- Task that ignores ctx: holds its slot until it returns (executor contract); covered for shutdown by the builder's `TestConcurrency_ShutdownDrainIsBounded`.
- ctx cancelled between `acquireSlot` and `pollWork` returning, and between the assignment and `running.Add(1)`: `Audit_ShutdownRacesPoll` PASS, 2 x 100 iterations: "before_response: assignment handed to an attempt goroutine in 0, dropped by the poll loop in 100"; "after_response: ... in 40, dropped ... in 60". Run always returns, running 0, no result, goroutines back to baseline (O-2).
- Code reading: `running` changes only while the token is held (increment after acquire in the poll loop, decrement before `<-sem` in the single deferred release); `drain` is called from the poll loop, so no increment can race its `running == 0` check. I found no path where running exceeds `TotalSlots`, goes negative or leaks.
Result: **PASS**.

### 3. Shutdown (executed)
Real binaries, `run-binary.sh shutdown-fifo-s4 fifo_pull 4 4 10000 "" "" 3` (`run-shutdown-fifo-s4/summary.txt`, `worker.log`, `proxy.log`):
- "RUNNING attempts just before SIGTERM: 4"; "worker SIGTERM -> exit: 3 ms, exit code 0".
- Leases left to expire: "attempt states right after worker exit: RUNNING=4"; "attempt states 45 s later: LOST=4"; "job states 45 s later: RETRYING=4". The attempts were marked LOST at 34.47 to 34.51 s (started 0.10 to 0.13 s; 30 s lease + 5 s sweeper).
- No double result report: 0 `/result` requests in `proxy.log` (7 requests: register, 1 heartbeat, 4 polls 200, 1 poll 204), 0 rows in `results`. Each attempt logged "result delivery interrupted by shutdown" once. Consequence (ADR-0014 behaviour kept, inferred cost): every attempt running at SIGTERM is retried and consumes one of `max_attempts`; with 4 slots that is up to 4 per shutdown instead of 1.
- Idle shutdown on the real binary: 48 ms to 174 ms (`par-*/summary.txt`).
- Goroutine leak: not observable on a process that exits; in-process, `TestConcurrency_ShutdownDrainsWithoutLeaks` (builder, 50/50) and my `Audit_ShutdownRacesPoll` (goroutines back to baseline after 200 shutdowns) PASS.
- 60 s drain bound for an ignoring task: no registered task ignores its context (code reading: `sleep.go` selects on `ctx.Done()`, `sha256_loop.go` checks it every 1,024 iterations, `echo` does not block), so it cannot be reached with the real binary. On the fake clock the builder's `TestConcurrency_ShutdownDrainIsBounded` passed 50 of 50 (Run blocks until the 60 s timer fires, then returns and logs `running=1`).
- `heartbeatWG.Wait` hang: not possible (section 10, `Audit_HungHeartbeatDoesNotHangShutdown`); but nothing in the builder suite proves the wait exists (A-1).
**PASS**, with A-1 and A-4.

### 4. Heartbeat / register truthfulness (executed + code reading)
Register at start reports `TotalSlots` (running is 0 before the pool starts). Heartbeat and re-register after 404 report `TotalSlots - running` (builder tests, mutant c killed by 3). The one window where the number overstates free capacity: a slot held by an in-flight poll counts as free, `Audit_AvailableSlotsDuringInFlightPoll`: "available_slots=1 (running=0)" with the only slot held by a poll. This is the meaning ADR-0019 Section 2.1 defines, and the coordinator ignores the field (SEC-055), so it is not harmful today; V2-1/V2-3 must read it with that meaning. **PASS**.
