Branch / last commit: agent/claude/P4-20, work tip eff133a (fix) plus the audit commit that carries this file.

## Cause (confirmed by code reading, then executed)
`TestSecurity_PartD_LeakScan` in `tests/integration/part_d_security_test.go` builds and starts the real coordinator itself and set no `MINICLOUD_DISPATCH_POLICY`. Since P4-17 an unset policy means `round_robin` (`dispatchPolicyFromEnv` in `internal/config/config.go`). Under round_robin a poll never claims an unreserved job (ADR-0017 D5); a worker must be polled-fresh (D7) before the assignment pass (default every 1s) reserves the job. The test polled exactly once and fatalled on 204. P4-17 fixed the shared rig (`CoordinatorEnv` in `tests/internal/sectest/proc.go` states `fifo_pull`), but this test builds its own env and was missed. The policy default is the cause, so the stop condition did not trigger.
Executed: in the new test below, on the default policy, the assignment arrived on poll 4 or 5 (4 runs: 5, 5, 5, 4); polls 1 to 3 or 4 returned 204 (`evidence/green.log`, `evidence/audit-integration-db.log`).

## What changed
- `tests/integration/part_d_security_test.go`: `pollUntilAssignment` (hard bound `leakScanPollMax` = 20 polls, `leakScanPollEvery` = 250ms, about 5s; stops on the first 200; any status other than 200/204 fails at once; exhaustion error names the bound). LeakScan uses it and stays on the DEFAULT policy; its env sets `MINICLOUD_DISPATCH_POLICY=` (empty = default) so an exported value cannot change the policy under test. LeakScan needs no fifo_pull for its own reason.
- `tests/integration/leakscan_poll_test.go` (new): `TestLeakScanPollHelper_DefaultPolicy`, runs the same register, submit, poll flow against the real coordinator binary on the default policy, with no container control.
- No production code changed.
