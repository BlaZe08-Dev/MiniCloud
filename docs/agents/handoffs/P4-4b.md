## Design decisions and deviations (with reasons)

- **D1 Backoff is a parameter of the sweep (answers Q-4b-1: yes, 4b owns it).** `SweepParams.Backoff` is a `domain.BackoffFunc` supplied by the caller (`policy.BackoffFunc(rnd)`). Repositories contain no randomness. A nil `Backoff` is rejected with `ErrInvalidRequest` and mutates nothing (no hidden default randomness).
- **D2 Cap applies before jitter.** ADR-0015 writes `min(30 s, 1 s * 2^(n-1)) * jitter`; I implemented exactly that, so the longest delay is 45 s. If "cap 30 s" was meant to bound the final delay, `ComputeBackoff` changes in one place and `TestDomain_ComputeBackoff_FullJitter` rows change (Q-3).
- **D3 Grace input shape.** `SweepGraceState{StartupGraceUntil, OutageWindowUntil, CooldownUntil}`, absolute instants compared with the repository clock inside the locks. Reading chosen: suppressed if `now < StartupGraceUntil`; else not suppressed if `now < CooldownUntil` ("reaping proceeds during cooldown"); else suppressed if `now < OutageWindowUntil`. The zero value suppresses nothing (a caller that forgets grace reaps; see security S3). Q-1 and Q-2.
- **D4 `RenewLease` records no event.** `docs/state-machine.md` section 5 lists `LEASE_RENEWED`, but neither ADR-0014, protocol 6.1 nor the plan's 4b scope asks the repository to write it, and one row per renewal every 10 s per attempt is unbounded audit growth. Pinned by `TestConformance_RenewLease_AcceptUntilSwept` (event count unchanged). Q-4.
- **D5 Renewal evaluation order mirrors commit** (protocol 6.3): terminal job, then LOST attempt of this job (`ErrLeaseExpired`), then superseded / not RUNNING / wrong token / unknown attempt id (`ErrStaleAttempt`), then wrong worker (`ErrWorkerMismatch`). Two consequences: an unknown attempt id is 409 `STALE_ATTEMPT_REJECTED`, not 404 `ATTEMPT_NOT_FOUND` (the protocol table lists stale at priority 3 and not-found at 6; commit has always behaved this way); and a rejected renewal writes nothing (no diagnostic event, no attempt closure; the sweeper closes it later). Q-5.
- **D6 LOST is evaluated before token mismatch** (ADR order): a caller who knows a job id and an attempt id, with no token, can distinguish "swept" (409 `LEASE_EXPIRED`) from "stale". On a commit it also writes the one bounded diagnostic. Same class as SEC-024; see security F-4b-1.
- **D7 What a sweep writes.** LOST attempts get `error_class = LEASE_EXPIRED`, `error = "lease expired: worker failed to renew"` (also when the job was already terminal and for exhausted jobs); CANCELLED attempts get no class. Events: terminal job -> `LEASE_EXPIRED`; `CANCEL_REQUESTED` -> only `JOB_CANCELLED` (`resolved_by: lease_sweeper`); retry -> `LEASE_EXPIRED`, `JOB_RETRYING` (`attempt_no`, `not_before`, `backoff_seconds`); exhausted -> `LEASE_EXPIRED`, `JOB_FAILED` (`error: "max attempts exhausted"`, `error_class`). A job failed by the sweeper has **no `results` row** (no worker reported an exit code); `GET job` shows no `result`. Q-6.
- **D8 `DispatchNextJob`/`DispatchJob` treat `not_before IS NULL` as due**, to match the in-memory rule (nil = immediately). The plan's literal SQL is `not_before <= clock_timestamp()`; they differ only for a RETRYING row with NULL `not_before`, which no code path produces.
- **D9 A sweep skips a job in a state with no rule** (a RUNNING attempt under a QUEUED/SUBMITTED/RETRYING job). It counts it in `SkippedChanged` and mutates nothing. Unreachable through the public API; it would never self-heal (F-4b-3).
- **D10 Migration.** Follows `docs/schema.md` exactly. Existing attempts, in any state, get `lease_expires_at = migration time + 30 s` from the temporary default (a pre-upgrade RUNNING attempt is not instantly reapable and can still commit: tested). The unique diagnostic index cannot be built over existing duplicates; the migration then **fails loudly and rolls back** rather than deleting audit rows (tested). The shipped code never wrote duplicates. `attempts.last_error` exists but has no writer until 4d.
- **D11 `ErrLeaseExpired` HTTP mapping** is the only `internal/api` edit (see above).
- **D12 4a model test not extended.** `TestProperty_StateMachine_ModelConformance` still has no lease/sweep operations; the new race test and conformance suites cover them instead.
- **D13 Constants.** `DefaultRetryPolicy().DefaultMaxAttempts` (3) duplicates `coordinator.DefaultMaxAttempts`; I did not touch the coordinator. 4d can unify.
- Plan statements checked and found consistent with the code: sweep resolution rules (R-02), `LOST` consumes `max_attempts`, RETRYING cancel clears `not_before`.

## Open questions for the orchestrator

- **Q-1 (4c) clock domain of the grace instants.** `SweepGraceState` carries absolute `time.Time`s that the repository compares with *database* time. The coordinator will compute them from *process* time. V1 runs both on one host, so skew is tiny, but they are different clocks. Options: keep (document the same-host assumption), or pass durations ("suppress for the next X").
- **Q-2 cooldown inside the lock.** I let an active `CooldownUntil` override an open `OutageWindowUntil` (and not the startup grace). The plan lists the cooldown in the input but never says what the in-lock check does with it. Confirm or say the repository should ignore it.
- **Q-3 backoff cap** (D2): 45 s maximum (formula as written) or 30 s hard cap?
- **Q-4 `LEASE_RENEWED` event** (D4): confirm no event per renewal, or specify a bounded form.
- **Q-5 unknown attempt id on renewal** (D5): 409 stale (as commit) or 404 `ATTEMPT_NOT_FOUND`? 4c's worker treats both as terminal; the difference is only the code.
- **Q-6 sweeper-failed jobs have no result** (D7): should `GET /v1/jobs/{id}` expose the failure (for example `result.error = "max attempts exhausted"`)? That needs a `results` row (exit code NOT NULL) or an API-side projection from events; 4d should decide when classification lands.
- **Q-7 (4c) sweep skipped-state reporting.** `SweepResult` separates `SkippedLocked` (benign) from errors (failed tick). 4c's tick must treat only a returned error as a failed tick, as the plan says; confirm 4c should also log `SkippedChanged` anomalies.
- **Q-8 (4c/4d) renewal on a terminal job or LOST attempt writes nothing** (D5). Protocol 6.3's "Diagnostic Event Written? Yes" column is written for `/result` and `/renew` together; I applied it to commits only. Confirm.
- **Q-9 (4d)** the stress test only samples sweeps; if the owner wants a stronger Invariant 4 signal, the targeted race test is the one to extend.

## Security review

**Assumptions challenged**
- S1 Lock order and deadlock freedom. Challenge: could the sweeper and a commit/renew/cancel/dispatch deadlock? Evidence: **executed** `TestPostgresRepository_Sweeper_CanonicalLockOrder` (observed holds while parked), mutation l1/l2; stress and race tests 20/20 with `-race`. Commit and renew lock `jobs` then `attempts` (a subsequence of the canonical order); the sweeper is the only code taking `workers` after `jobs`, and `DispatchNextJob` does the same order. **confirmed by code reading** that no path locks `attempts` before `jobs`.
- S2 A lock timeout or SKIP LOCKED skip must not look like an outage. **executed** (`..._CanonicalLockOrder` subtests, `SkippedLocked`, nil error). Corollary, **confirmed by code reading**: a lock_timeout on the *jobs* statement cannot happen (SKIP LOCKED never waits); a 55P03 there would surface as an error (mutation l2 shows that failure mode).
- S3 Grace is fail-open for reaping: the zero `SweepGraceState` reaps. A coordinator that forgets to pass grace reaps healthy attempts after a restart and causes duplicate execution (at-least-once, invariant 5). The repository cannot know. **inferred**; 4c's `TestCoordinator_LeaseSweeper_StartupGrace_SuppressesReaping` (planned test) is the guard.
- S4 Renewal must not extend a cancelled job's lease or resurrect a swept attempt. **executed** (n1/n2, `..._RejectedAfterLost`, in-memory clock test).
- S5 A late commit must never write `results` for a swept attempt. **executed** (`..._ConflictEvaluationOrder`, `..._LostAttemptDiagnosticBoundedByIndex`, race test: no results row with LOST).
- S6 Unauthenticated audit-table growth (SEC-004). Bounded to one `DIAGNOSTIC_LATE_RESULT` per (job, attempt) by the unique index; a foreign or unknown attempt id records nothing. **executed** (d1/d2, m1).
- S7 Session state leak: the sweeper's `lock_timeout` is transaction-local. **executed** (`..._LockTimeoutDoesNotLeakToPool`, k1).
- S8 SQL construction: no dynamic SQL; durations and timestamps are parameters. The SEC-005 AST test passes. **executed**.
- S9 Migration safety on a database with data. **executed** (upgrade test, fail-loud test); constraint additions use NOT VALID then VALIDATE; the only table rewrite-free default is a stable expression.

**Attacks tried (real tests)**: 20 racing commits on a terminal job and 20 on a swept attempt; renew/commit/cancel vs four sweepers over 24 expired attempts (x20); sweeper parked on workers/attempts/jobs locks; renewal and commit landing between scan and lock; wrong token / wrong worker / unknown / foreign / non-RUNNING attempt on renew and commit; renewal on terminal and CANCEL_REQUESTED jobs; nil backoff; grace on running, cancel-requested and terminal jobs; duplicate diagnostics inserted directly in SQL; legacy rows through the migration.

**Not tested**: database outage or connection loss in the middle of a sweep batch (partial results returned with the error; per-candidate commits make it safe by code reading only); a real coordinator clock vs database clock skew (Q-1); more than one sweeper process across machines beyond the 4 goroutines; `ctx` cancellation mid-sweep; a RUNNING attempt under a non-RUNNING job (D9); behavior with `max_attempts` 20 and repeated losses beyond the 3-attempt tests; wrong-token variants of the existing 4a terminal-commit path.

**Findings**
- **F-4b-1 (Informational, within SEC-004, same class as SEC-024).** Because LOST is evaluated before the token check (ADR order, D6), an unauthenticated caller who knows a job id and an attempt id can learn that an attempt was swept, and a commit naming it writes the one bounded diagnostic event. Evidence: **executed** (`..._ConflictEvaluationOrder`, "wrong token on a LOST attempt: ErrLeaseExpired"). Suggested: if unwanted, check the token before the LOST branch; costs one design change.
- **F-4b-2 (Low).** PostgreSQL attempt ids are `att_<jobID>_<n>`, so the attempt id is derivable from a job id; F-4b-1 is therefore reachable with only a job id. Pre-existing format, relevant now. Evidence: **confirmed by code reading** (dispatch builds the id).
- **F-4b-3 (Low).** The sweeper never closes a RUNNING attempt under a job in QUEUED, SUBMITTED or RETRYING. Unreachable through the public API; if an operator or a future bug produces it the attempt would hold a worker slot forever. Evidence: **confirmed by code reading** (`default:` branch in both sweeps); not executed.
- **F-4b-4 (Informational).** `TestPostgresRepository_Concurrency_MixedOperationsStress` passed 20/20 but sampled only 3 sweeps in total (log: "stress: N attempts swept"), so by itself it is a weak sweep detector; the deterministic proofs are the conformance, lock-order and re-check tests, and the targeted race test (both outcomes sweep-wins and commit-wins occur in its log). Evidence: **executed**.
- **F-4b-5 (Informational).** A swept job that fails has no `results` row and no `error` visible on `GET job` (Q-6). Evidence: **executed** (`..._RetryOrFail` asserts `Result == nil`).
- SEC-023 remains open for the old migrator test (not edited); SEC-024 behavior unchanged on the terminal path.
