# Handoff P4-14

Branch / last commit: `agent/gemini/P4-14`

## What changed (by package)
- `internal/worker`:
  - `client.go`:
    - Fixed integer shift overflow in `ComputeBackoffWithJitter` (finding F-5c2-1). Previously, `multiplier := 1 << (failureCount - 1)` overflowed for `failureCount >= 64`, producing a negative int64 at count 64 and 0 at count 65+, which bypassed `if multiplier > 16` and resulted in 0 s backoff. Replaced with pre-shift clamp:
      ```go
      shift := failureCount - 1
      if shift > 4 {
          shift = 4
      }
      multiplier := 1 << shift
      ```
      This guarantees multiplier is strictly in `{1, 2, 4, 8, 16}` for all `failureCount >= 1` up to `math.MaxInt`, preserving exact doubling growth for counts 1..5, capping at 16x without overflow, and guaranteeing backoff is always positive (`> 0`) and never exceeds `max`.
  - `client_test.go`:
    - Imported `"math"`.
    - Preserved existing `TestComputeBackoffWithJitter` unchanged.
    - Added `TestComputeBackoffWithJitter_Table`: checks counts 0..200 plus 62, 63, 64, 65, 127, 128, and `math.MaxInt`. Verifies `backoff > 0`, `backoff <= max`, exact base for non-positive counts, and jitter bounds `[0.5*dur, dur]` matching the 16x multiplier cap.
    - Added `TestComputeBackoffWithJitter_Property`: checks property for all counts 0..1000 across multiple `(base, max)` configurations.
- `docs/agents/TASKS.md`:
  - Registered task `P4-14` in Active table and task description section.
- `docs/agents/handoffs/P4-14-evidence/`:
  - Added `mutation-index.md` indexing single-site mutations M1, M2, and M2b.
  - Added diffs and execution logs: `mutant-1-remove-clamp.diff`, `mutant-1-remove-clamp.txt`, `mutant-2-clamp-too-late.diff`, `mutant-2-clamp-too-late.txt`, `mutant-2b-clamp-shift-step-too-late.diff`, `mutant-2b-clamp-shift-step-too-late.txt`.

## Design decisions and deviations from the design doc (with reasons)
- Pre-shift clamp `shift := failureCount - 1; if shift > 4 { shift = 4 }; multiplier := 1 << shift`:
  - Preserves exact growth for non-overflow counts (multipliers 1, 2, 4, 8, 16).
  - Eliminates shift overflow for any `failureCount` from 0 up to `math.MaxInt`.
  - Does not change any function signature or package constant.
- Checked git grep for other instances of `ComputeBackoffWithJitter` or callers doing their own shifting: confirmed exactly one definition in `internal/worker/client.go` and all 4 callers pass raw failure count variables without pre-shifting.

## Security review
- Assumptions challenged:
  - Challenged assumption that `ComputeBackoffWithJitter` was only called with small failure counts. In long network or coordinator outages, `consecutiveFailures` increases indefinitely (e.g. 64+ poll failures over minutes/hours). Without pre-shift clamp, the worker entered a tight polling loop sleeping 0s.
  - Checked whether callers in `client.go` performed manual shifting: verified callers pass raw counts `consecutiveFailures`, `failures`, or `n`.
- Attacks tried:
  - Boundary attacks with counts 62, 63, 64, 65, 127, 128, `math.MaxInt`, 0, -1, and `math.MinInt`.
- Not tested:
  - External process time manipulation (wall-clock drift does not affect deterministic duration calculations).
- Findings with evidence labels:
  - Finding F-5c2-1 (overflow in `ComputeBackoffWithJitter` at count 64+): confirmed by code reading and reproduction; fixed and verified by executed tests and mutation proofs (evidence label: **executed**).
