## What changed (by package)

- `internal/worker/client.go`
  - **Pool:** `Run` replaces the inline `ExecuteAndReport` with a bounded pool. It uses a semaphore of `TotalSlots`. A slot is acquired before every `pollWork` (func `acquireSlot`). Each assignment runs in its own goroutine (func `runAttempt`), tracked by a `WaitGroup`.
  - **Slot release:** a single `defer` releases the slot. It first recovers a panic and logs only the job and attempt IDs and the panic type.
  - **Shutdown:** a bounded drain (func `drain`, `ResultDeliveryBudget` on the agent clock, no timer when nothing runs). `Run` now also waits for its heartbeat goroutine.
  - **Live slots:** `register` and `sendHeartbeat` report func `availableSlots` = `TotalSlots` minus running attempts.
  - **Unchanged:** `ExecuteAndReport`, `deliverResult`, `renewLoop`, `ComputeBackoffWithJitter`, `pollSleep`, the `Clock` seam and all poll error handling. The poll error branches were only re-indented, plus one `<-sem` before them.
- `internal/worker/export_test.go`: these test seams: `SetSlotWaitHook`, `SetAttemptDoneHook`, `RunningForTest`, `AvailableSlotsForTest`, `SendHeartbeatForTest`, `CloseIdleConnectionsForTest`.
- `internal/worker/concurrency_test.go`: 11 tests (new file).
- `internal/config/config.go`: new constant `MaxWorkerSlots = 1024`. `LoadWorkerConfig` now rejects `MINICLOUD_WORKER_SLOTS` above it with a message naming the variable (ADR-0019 Section 2.6, owner answer Q2).

## Design decisions and deviations from the design doc

- **Exact counts in the heartbeat test:** the heartbeat test first assumed `running` increments when the task starts. It actually increments when the poll loop hands the assignment to its goroutine. That is earlier, and is exactly what ADR-0019 Section 2.1 says. The first `-race -count=20` run caught it: 1 FAIL, `heartbeat with 2 running = 0, want 1`. The fix is in the test: the fake coordinator hands out one assignment at a time on the way up. No production change.
- **Second test hook:** I added an attempt-done hook alongside the slot-wait hook the ADR named. It gives each slot release an event, so the down-phase heartbeat checks and the release checks never sleep.
- **No timer when idle:** the drain creates no timer when nothing is running. Without this, `TestPollTiming_RunSleepsWithinMaxBackoff`, which records every agent timer, would have seen a 60 s timer. Recorded in ADR Section 2.5.
- **Config test location:** `TestLoadWorkerConfig_SlotsUpperBound` lives in `internal/worker`, not `internal/config`. It compares `config.MaxWorkerSlots` with `coordinator.MaxWorkerSlots`, and the worker package already imports both. This kept the config change to `config.go`, as the scope says.
- **pollSleep and cancel:** `pollSleep` still ignores `ctx`, as in V1. A loop sleeping on the fake clock therefore needs a clock advance to see cancellation. The test rig does this in `stop`. On the real clock the longest such wait is `MaxPollBackoff`, as before.

## Security review

**Assumptions challenged:**
- One attempt's failure could take down the others (now a recovered panic).
- Slots could leak or be double-released.
- Results or lease tokens could cross between concurrent attempts.
- A full worker could still poll.
- Shutdown could hang or leak goroutines.
- A typo in slots could exhaust resources.

**Attacks and tests (executed):**
- Panic and log hygiene: `TestConcurrency_SlotReleasedOnEveryExit`/panic. The log is checked for neither the payload marker nor the lease token.
- Token and result crossing: `TestConcurrency_ResultsNeverCrossBetweenAttempts`. The fake coordinator checks the token, attempt and worker on every renew and result.
- Lost-lease isolation: `TestConcurrency_LostLeaseIsolatedToOneAttempt`.
- Poll while full: `TestConcurrency_FullWorkerDoesNotPoll`, plus the full-poll check inside every rig test.
- Leaks: `TestConcurrency_ShutdownDrainsWithoutLeaks`.
- Hang on an uncooperative task: `TestConcurrency_ShutdownDrainIsBounded`.
- Slots typo: `TestLoadWorkerConfig_SlotsUpperBound`.
- Race detector: 20 runs, plus the full race suite.

**Not tested:**
- Real-process parallel runs under `fifo_pull`.
- Behaviour with 1024 slots (the resource estimate in ADR Section 2.6 is inferred).
- A panic inside the renewal or delivery goroutines. These are agent code, not task code, and are not recovered, which is unchanged.

**Findings:**
- No new security finding.
- **Behaviour change (Low, confirmed by code reading and tests):** a task panic no longer exits the worker; it costs one lease duration before the retry (ADR-0019 Section 2.3, owner answer Q3).
- **O1 (inferred, not tested):** carried as a V1.0.x candidate. It is not registered in `docs/security/findings.md`, which this task does not own.
