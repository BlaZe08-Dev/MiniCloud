## Design decisions and findings (ADR-0017 notes 31 to 36)
- The ADR's three API abuse tests carry the abuse prefix so `make test-security` runs them (note 31).
- A worker is eligible only if it polled within the accept window. Two consequences are now exercised: a silent worker drops out one window after its last poll, and a late poll that finds the pass heartbeat stale runs the refresh itself, so it can claim the job it just lapsed (note 32). Section 6.1's FS-22 text describes the case with a fresh heartbeat; the test runs the pass first, as the loop does.
- The PostgreSQL variants cannot skip over a sweeper grace window by shifting stored times; FS-17 uses a 2 s startup grace and a real wait (note 33).
- Finding (documentation, not code): the Section 6.2 round-trip bound `6 + 2T + 4W` is below the measured cost, about 7 round trips per reservation and 2 per revoke (note 35). The attempt rate it feeds is pinned and unaffected. No change made.
