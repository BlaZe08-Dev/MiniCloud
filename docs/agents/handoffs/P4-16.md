## What changed (by package)
- `internal/config/config.go` only (production). `getIntEnv` and `getDurationEnv` now return `(value, error)`: unset or empty gives the default; a value that does not parse (overflow included) is an error. New `getPositiveIntEnv` and `getPositiveDurationEnv` also reject zero and negative. `LoadCoordinatorConfig` keeps the first error and returns it before any cross-variable validation; `LoadWorkerConfig` returns the error directly.
- Matched the newer helpers `lookupIntEnvStrict` and `lookupDurationEnvStrict`: messages `%s must be an integer (got %q)` and `%s must be a duration with a unit, such as 5s (got %q)`. Positive rule: `%s must be positive (got %q)`.
- Deviation (required by the task): the strict helpers treat a set but empty value as an error; the older helpers keep empty as the default, as before.
