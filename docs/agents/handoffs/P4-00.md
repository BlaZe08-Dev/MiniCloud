## Summary of Design Changes
The Phase 4 design underwent extensive refinement to resolve contradictions identified during the Claude Code audit (`docs/agents/reviews/P4-00.md`) and align with owner decisions:
1. **Symmetric Accept-Until-Swept Rule:** Eliminated the contradiction where renewals and commits were required to evaluate an "unexpired" lease timestamp. Leases grant exclusive execution rights until reaped by the sweeper. While `attempts.state == 'RUNNING'`, both renewal and commit succeed even after `lease_expires_at` has passed on database time.
2. **Canonical Sweeper Concurrency & Outage Grace:** Specified one canonical locking pattern (`SELECT jobs ... FOR UPDATE SKIP LOCKED` followed by plain `FOR UPDATE` under `lock_timeout` on workers and attempts, with one grace check inside locks). Eliminated impossible `SKIP LOCKED` + `NOWAIT` syntax. Replaced wall-clock and /readyz outage heuristics with autonomous database-clock gap detection (> 3x sweep interval) and failed-tick detection, protected by a 30s grace window and 30s cooldown.
3. **Cancellation Races & Slot Leak Prevention (SEC-022):** Resolved the duplicate cancel bug where a second cancel on `CANCEL_REQUESTED` bypassed worker preemption and leaked worker capacity. Duplicate cancels are now an idempotent HTTP 200 no-op returning state `CANCEL_REQUESTED` with identical response body, changing nothing. If a job reaches a terminal state, a late `CommitAttempt` marks the attempt closed and frees the worker slot in the same transaction while returning HTTP 409 `JOB_ALREADY_TERMINAL`. Sweepers clean up `RUNNING` attempts on terminal jobs to `CANCELLED` or `LOST` without modifying the job state.
4. **Failure Classification & Error Codes:** Bounded `error_class` values to exactly four (`PERMANENT`, `TRANSIENT`, `UNKNOWN`, `LEASE_EXPIRED`), dropping `INFRASTRUCTURE_FAULT`. Created an unambiguous 3-tier HTTP 409 conflict evaluation table. Added missing 400 and 503 error codes to cancel endpoint.
5. **Worker Protocols & Multi-Version Compatibility:** Worker keys on structured error codes in the response body. If renewal receives an un-enveloped 404, it detects an old coordinator version, logs once, and continues running without renewal. If renewal receives 400, it logs an error and continues executing. Moved worker delivery retry loop to Slice 4c alongside worker renewal goroutines.
6. **In-Memory & PostgreSQL Parity:** Unified direct `RETRYING -> RUNNING` dispatch in `repo.DispatchNextJob` across both in-memory and PostgreSQL storage implementations, rewiring the in-memory coordinator in Slice 4a.
7. **Document Hygiene & Grounded Citations:** Audited `docs/source/MiniCloud_Project_Blueprint.pdf` (14 pages) to ground all architectural citations strictly in existing sections (3, 5, 8, 10, 13). Replaced all LaTeX math notation ($...$) with standard Markdown across all documentation files.

## Security review
- **Assumptions challenged**:
  - *Assumption*: Duplicate `CancelJob` calls on a `CANCEL_REQUESTED` job were harmless idempotent operations.
    - *Result*: Proven false by audit probe `TestReviewP400_SEC022_DoubleCancelLeaksWorkerSlot` (planned test). The storage layer transitioned the job immediately to `CANCELLED`, causing the worker's subsequent cooperative commit to be rejected with 409 `JOB_ALREADY_TERMINAL`, leaving the attempt `RUNNING` in the database and permanently leaking worker slot capacity (SEC-022).
  - *Assumption*: Leases expired automatically on the database clock and should immediately block renewal or commit requests.
    - *Result*: Proven flawed. Requiring unexpired leases on renewal or commit caused cascading aborts during coordinator restarts or transient network delays. Resolved by the symmetric accept-until-swept rule: exclusive rights persist until the background sweeper reaps the attempt to `LOST`.
  - *Assumption*: Coordinator sweeper could use wall-clock timestamps or `/readyz` connectivity to detect database outages.
    - *Result*: Proven ungrounded. `/readyz` only measures coordinator-to-DB ping reachability, not background sweeper tick health. Wall-clock gaps drift under NTP or VM pause. Resolved by using database-clock timestamps (`clock_timestamp()`) and measuring tick execution gaps (> 3x sweep interval) with autonomous 30s grace windows.
  - *Assumption*: PostgreSQL sweeper could combine `SKIP LOCKED` and `NOWAIT`.
    - *Result*: Proven invalid SQL syntax in PostgreSQL. Replaced with canonical locking: `SELECT jobs ... FOR UPDATE SKIP LOCKED`, followed by plain `FOR UPDATE` on workers and attempts under `lock_timeout`.
- **Attacks designed with planned-test names**:
  - `TestReviewP400_SEC022_DoubleCancelLeaksWorkerSlot` (planned test): Verifies that duplicate cancel on `CANCEL_REQUESTED` does not bypass worker preemption or leak worker capacity.
  - `TestConformance_CancelJob_IdempotentCancelRequested` (planned test): Verifies that duplicate cancel on `CANCEL_REQUESTED` returns HTTP 200 and keeps job in `CANCEL_REQUESTED`.
  - `TestPostgresRepository_Sweeper_TerminalJobResolution` (planned test): Verifies sweeper reaps `RUNNING` attempts on `CANCELLED` jobs to `CANCELLED` and on other terminal jobs to `LOST` without modifying job state.
  - `TestCoordinator_Sweeper_SlowTickOutageGrace` (planned test): Verifies that slow ticks where elapsed database time > 3x sweep interval trigger the 30s outage grace window.
  - `TestCoordinator_Sweeper_GraceCooldown` (planned test): Verifies that consecutive outage conditions do not restart the 30s grace window more often than once per 30s cooldown.
  - `TestWorker_RenewLease_MissingEndpointGrace` (planned test): Verifies worker encountering HTTP 404 without error envelope logs once and continues execution without failing.
  - `TestWorker_RenewLease_BadRequestHandling` (planned test): Verifies worker encountering HTTP 400 from renewal endpoint logs an error and continues execution.
