## What changed (by package)

### `cmd/mc`
- Added `cmd/mc/sanitize.go` containing `func sanitize(s string) string`:
  - Keeps printable runes (`unicode.IsPrint(r)`), newline (`\n`), and horizontal tab (`\t`).
  - Converts CRLF line endings (`\r\n`) to standard newline (`\n`).
  - Neutralizes lone carriage returns (`\r` not followed by `\n`) by replacing them with visible escape string `\r`, preventing terminal cursor rewinds and line overwrites.
  - Replaces C0 control characters (`r < 0x20`) with hex placeholder `\x..` (e.g. `\x1b` for ESC, `\x00` for NUL, `\x07` for BEL, `\x08` for BS).
  - Replaces DEL (`0x7f`) with `\x7f`.
  - Replaces C1 control characters (`U+0080..U+009F`) with Unicode escape `\u00..` (e.g. `\u009b` for CSI).
  - Replaces any other unprintable Unicode code points with `\u....` or `\U........`.
  - Executes in a single zero-allocation-per-run pass using `strings.Builder`.
- Added `cmd/mc/sanitize_test.go`:
  - Table-driven unit tests (`TestSanitize`) verifying ESC clear-screen (`\x1b[2J`), OSC title change (`\x1b]0;pwned-title\x07`), backspace (`foo\x08\x08bar`), lone CR (`hello\rworld`), CRLF normalization (`line1\r\nline2\r\n`), multiple CRs before LF (`\r\r\n`), C1 controls (`\u0080\u009b`), DEL (`abc\x7fdef`), C0 controls (`\x00\x01`), valid UTF-8 text (`Hello, World! café 🚀 日本語 123`), tab/newline preservation, and empty strings.
  - Stress test `TestSanitize_VeryLongText` testing 65 KiB of printable text interspersed with control sequences and carriage returns, confirming no raw control bytes emerge.

## Print sites covered and rationale

### Print sites covered with `sanitize(...)`:
1. `cmd/mc/main.go` func `handleGet`:
   - `job.Result.Error`: worker-supplied string committed via `/v1/jobs/{id}/attempts/{attempt_id}/result`.
   - `job.Result.Output`: worker/task-supplied string committed via `/v1/jobs/{id}/attempts/{attempt_id}/result`.
   - `job.TaskType`: task-supplied identifier string.
2. `cmd/mc/failure.go` func `failureSummary`:
   - `last.Error`: worker-supplied string from `Attempt.Error` displayed in `mc get` failure details.
3. `cmd/mc/main.go` func `handleAttempts`:
   - `att.WorkerID`: worker identifier chosen by worker at registration.
4. `cmd/mc/main.go` func `handleWorkers`:
   - `worker.ID`: worker identifier chosen by worker at registration.
   - `worker.SupportedTasks`: task names advertised by worker at registration.
5. `cmd/mc/main.go` func `handleSubmit`:
   - `job.TaskType`: task identifier submitted by client.

### Print sites decided not to cover, with rationale:
1. `job.ID`, `att.ID`: coordinator-generated IDs (formatted by coordinator as `job_<N>_<hex>` and `att_<N>_<hex>`); not worker-supplied or task-supplied.
2. `job.State`, `att.State`, `att.ErrorClass`, `worker.Status`: internal domain typed enums (`domain.JobState`, `domain.AttemptState`, `domain.ErrorClass`, `domain.WorkerStatus`), validated centrally by the domain state machine; cannot contain control characters.
3. `job.CreatedAt`, `job.UpdatedAt`, `att.StartedAt`, `worker.LastHeartbeatAt`: `time.Time` values formatted with `time.RFC3339` or `"15:04:05"`.
4. `job.MaxAttempts`, `att.AttemptNo`, `att.ExitCode`, `worker.AvailableSlots`, `worker.TotalSlots`: integer numbers.
5. `worker.Version`: field exists in `domain.Worker`, but is not currently displayed in `mc workers` table columns (`ID`, `STATUS`, `AVAILABLE/TOTAL`, `LAST HEARTBEAT`, `TASKS`). If a version column is added in the future, it should use `sanitize(worker.Version)`.
6. Static CLI labels and table headers: hardcoded constant strings.

## Security review
- **Assumptions challenged**:
  - Assumed workers or task authors cannot control printed terminal output: refuted by F-4e-18. Unauthenticated workers under SEC-004 could register arbitrary error and output payloads containing ANSI escape codes, screen clears, title setting, and lone carriage returns to manipulate terminal state or hide malicious activity.
  - Assumed lone carriage returns (`\r`) are safe: challenged and mitigated. Lone carriage returns move cursor to column 0 without advancing the line, enabling line overwrite attacks (e.g. `Error: fake message\rREAL ERROR`). Lone CRs are escaped as visible `\r`, while standard CRLF (`\r\n`) line endings are normalized to LF (`\n`).
  - Assumed 8-bit ANSI escapes (C1 controls U+0080..U+009F) cannot bypass 7-bit ESC filters: challenged and mitigated. C1 code points (such as U+009B CSI) are converted to visible `\u00..` placeholders.
- **Attacks tried**:
  - ANSI ESC clear-screen sequence (`\x1b[2J`): neutralized to visible `\x1b[2J` (executed).
  - OSC terminal title manipulation (`\x1b]0;pwned-title\x07`): neutralized to visible `\x1b]0;pwned-title\x07` (executed).
  - Terminal backspace cursor manipulation (`\x08`): neutralized to visible `\x08` (executed).
  - Terminal line overwrite via lone carriage return (`\r`): neutralized to visible `\r` (executed).
  - 8-bit C1 control sequences (`\u0080\u009b`): neutralized to visible `\u0080\u009b` (executed).
  - Embedded raw NUL and control bytes (`\x00\x01`): neutralized to `\x00\x01` (executed).
- **Not tested**:
  - Terminal emulators with custom escape sequence extensions outside standard ANSI/OSC/C0/C1; mitigated because all non-printable Unicode runes and all control characters below 0x20 and DEL are escaped.
- **Findings with evidence labels**:
  - **SEC-048** (Low, Operator CLI Presentation): `mc get` and `mc attempts` print worker-supplied error strings raw to terminal without escaping ANSI control codes or escapes. Status: **Confirmed, Fixed (Slice P4-07)** [executed]. Verified via `TestAbuse_MCOutput_HostileErrorText` on both backends.
  - **SEC-031** (Informational, Storage / API Protocol): Unknown attempt ID under an existing job answers HTTP 409 `STALE_ATTEMPT_REJECTED`, not HTTP 404 `ATTEMPT_NOT_FOUND`. Status: **Documented** [confirmed by code reading and test execution].
