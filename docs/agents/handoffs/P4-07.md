## What changed (by package)

### `cmd/mc`
- `cmd/mc/sanitize.go`:
  - Implemented `func sanitize(s string) string`:
    - Keeps printable runes (`unicode.IsPrint(r)`), newline (`\n`), and horizontal tab (`\t`).
    - Converts CRLF line endings (`\r\n`) to standard newline (`\n`).
    - Neutralizes lone carriage returns (`\r` not followed by `\n`) by replacing them with visible escape string `\r`, preventing terminal cursor rewinds and line overwrites.
    - Replaces C0 control characters (`r < 0x20`) with hex placeholder `\x..` (e.g. `\x1b` for ESC, `\x00` for NUL, `\x07` for BEL, `\x08` for BS).
    - Replaces DEL (`0x7f`) with `\x7f`.
    - Replaces C1 control characters (`U+0080..U+009F`) with Unicode escape `\u00..` (e.g. `\u009b` for CSI).
    - Replaces invalid UTF-8 bytes (`r == utf8.RuneError && size == 1`) with hex placeholder `\x..` (e.g. `\xff`).
    - Replaces unprintable Unicode formatting runes (such as bidi overrides `U+202E`/`U+202D`, zero-width space `U+200B`, BOM `U+FEFF`, line/paragraph separators `U+2028`/`U+2029`, and NBSP `U+00A0`) with `\u....` or `\U........`.
    - Policy for NBSP (`U+00A0`): Escaped as `\u00a0`. NBSP renders visually identical to ASCII space (`0x20`), enabling terminal visual spoofing of task names, worker IDs, or CLI arguments. Escaping makes non-ASCII whitespace explicitly visible to operators.
  - Implemented `func sanitizeJSON(s string) string`:
    - Rewrites only C1 control characters (`U+0080..U+009F`) and DEL (`0x7f`) to JSON-valid `\u00xx` escapes while leaving all other bytes untouched.
    - Preserves valid JSON syntax and guarantees decode-equality with the original payload when decoded with `json.Unmarshal`.
- `cmd/mc/sanitize_test.go`:
  - Table-driven unit tests (`TestSanitize`) verifying ESC clear-screen (`\x1b[2J`), OSC title change (`\x1b]0;pwned-title\x07`), backspace (`foo\x08\x08bar`), lone CR (`hello\rworld`), CRLF normalization (`line1\r\nline2\r\n`), multiple CRs before LF (`\r\r\n`), C1 controls (`\u0080\u009b`), DEL (`abc\x7fdef`), NUL byte (`\x00`), C0 controls (`\x00\x01`), bidi overrides `U+202E` and `U+202D`, zero-width space `U+200B`, BOM `U+FEFF`, line/paragraph separators `U+2028` and `U+2029`, NBSP `U+00A0`, invalid UTF-8 bytes (`\xff\xfe\x80`), valid UTF-8 text, tab/newline preservation, and empty strings.
  - Stress test `TestSanitize_64KiBMixedHostileText` testing exactly 65,536 bytes (64 KiB) of mixed hostile text containing C0/C1 codes, lone CR, DEL, bidi overrides, NBSP, NUL, and invalid bytes, asserting the exact expected string.
  - `TestSanitizeJSON` asserting standard JSON passes untouched, hostile C1/DEL bytes are rewritten to `\u00xx` escapes, `json.Valid` returns true, and `json.Unmarshal` decode-equality holds against the original JSON.

## Security review
- **Assumptions challenged**:
  - Assumed workers or task authors cannot control printed terminal output: refuted by F-4e-18. Unauthenticated workers under SEC-004 could register arbitrary error and output payloads containing ANSI escape codes, screen clears, title setting, and lone carriage returns to manipulate terminal state or hide malicious activity.
  - Assumed lone carriage returns (`\r`) are safe: challenged and mitigated. Lone carriage returns move cursor to column 0 without advancing the line, enabling line overwrite attacks (e.g. `Error: fake message\rREAL ERROR`). Lone CRs are escaped as visible `\r`, while standard CRLF (`\r\n`) line endings are normalized to LF (`\n`).
  - Assumed 8-bit ANSI escapes (C1 controls U+0080..U+009F) cannot bypass 7-bit ESC filters: challenged and mitigated. C1 code points (such as U+009B CSI) are converted to visible `\u00..` placeholders.
  - Assumed raw JSON output is terminal-safe: challenged and mitigated. Standard `encoding/json` escapes bytes below 0x20 but leaves C1 characters and DEL unescaped. `sanitizeJSON` rewrites them to JSON-valid `\u00xx` escapes.
