## Design decisions and deviations

- Two variables must both be set: `MINICLOUD_ALLOW_CONTAINER_RESTART=1` and `MINICLOUD_CONFIRM_CONTAINER=minicloud-postgres`. A stray export of one does not enable the tests.
- Guard lives in `tests/integration` (package `integration_test`) rather than a shared testutil package: the only container-controlling tests are in that package, so a new package would add surface for no reuse.
- Defence in depth: besides the skip at the top of each test, the helpers that run docker fail the test if the opt-in is absent. This matters because the tests register a `t.Cleanup` that calls `startPostgresContainer`; a future test that forgets the skip would hit the hard failure before docker.
- The static scans (`TestEveryContainerRestartingTestCallsTheGuard`, `TestEveryTestURLConsumerHasNameGuard`) are an addition beyond the brief, so a new unguarded test fails the default run instead of relying on review. They parse source with go/ast and never connect or execute a test.
- Deviation, count: the unset-run PASS count rises by 5 (new unit tests), SKIP and FAIL unchanged; `make test-db` PASS rises by 2 (the two new postgres tests; the new integration tests are outside its anchored `-run`). No existing test was removed, skipped or loosened.
- Authorisations: none beyond the planning-session brief for P4-T1 (owned files, forbidden files, the hard rule never to run a container-restarting test with the opt-in on). No authorisation to run `make test-outage` was given and it was not run.

## Security review

Assumptions challenged:
- "Outage tests skip when the URL is unset" is true but is the hazard: with the URL set they ran. Now they additionally need two explicit variables. (executed: default run with the URL unset skips unchanged, 35 SKIP; guard truth table executed in `TestContainerControlAllowed`; not executed: the outage tests themselves with the URL set, by rule.)
- "Anchored `-run` proves the test ran": false, `go test -run` exits 0 on no match. (executed: `falsegreen.log`, `mut2.log`.)

Attacks tried:
- One variable only, wrong container name, empty name, opt-in `true` instead of `1`: `TestContainerControlAllowed` (executed).
- A forgotten guard in a future container test: `TestEveryContainerRestartingTestCallsTheGuard` plus helper hard failure (executed for the scan via mutation; helper hard failure confirmed by code reading, not executed because triggering it needs the docker path adjacent code).
