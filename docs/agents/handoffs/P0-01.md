## Design decisions and deviations from the design doc (with reasons)
1. **Database names changed to `minicloud_claude_test` / `minicloud_gemini_test`**
   (the brief and the draft said `minicloud_test_claude` / `minicloud_test_gemini`).
   Every Postgres test helper requires names ending in `_test`. With the brief's name,
   the tests fail (executed, password redacted):
   ```

       migrator_test.go:136: SAFETY VIOLATION: refusing to run test against database "minicloud_test_claude"; name must end in '_test'

       migrator_test.go:159: SAFETY VIOLATION: refusing to run test against database "minicloud_test_claude"; name must end in '_test'
   --- FAIL: TestMigrator_ConcurrentMigrators_ExactlyOneApplies (0.00s)
       migrator_test.go:195: SAFETY VIOLATION: refusing to run test against database "minicloud_test_claude"; name must end in '_test'
   --- FAIL: TestMigrator_NotSubjectToCoordinatorQueryTimeout (0.00s)
       migrator_test.go:654: SAFETY VIOLATION: refusing to run test against database "minicloud_test_claude"; name must end in '_test'
   --- FAIL: TestPostgresRepository_Security_WorkerCheckConstraints (0.00s)
       security_test.go:890: SAFETY VIOLATION: refusing to run test against database "minicloud_test_claude"; name must end in '_test'
   ```

   The owner chose the suffix-preserving names during the session. The guard is
   unchanged. `AGENTS.md` sections 5 and 9 use the new names.
2. **No Makefile change.** Section 9 uses `docker exec minicloud-postgres` by
   container name. That works from any worktree without a second compose project, so no
   new target was needed. `make db-reset-test` stays hard-wired to `minicloud_test`;
   section 9 tells agents not to run it.
3. **Forward references to P4-00 files reworded.** The checker has no "planned"
   exemption for paths (Rule A) or ADRs (Rule E), only the allowlist, which P0-01 does
   not own. The draft cited the Phase 4 plan doc, a fault-injection plan doc, the
   ADRs numbered 0014 to 0016 and the P4-00 review file, none of which exist on `main`. They are now
   described in prose as "arrives with P4-00, not on `main` yet". Once P4-00 merges,
   the context map should get the exact paths back (open question 1).
4. Section numbers 1–10 are unchanged (new material went into subsections), because
   `TASKS.md` and the brief refer to sections by number.

## Security review
- **Assumption challenged: "per-worktree databases isolate the agents."** Executed: the
  stats query shows only `minicloud_claude_test` changing during `make test-db`.
  Isolation holds only if each agent's `.env` points at its own database; nothing
  enforces that. A worktree with an unedited `.env` still uses the shared
  `minicloud_test`.
- **Attack tried: point the tests at a database whose name does not end in `_test`.**
  Executed against a nonexistent name (`minicloud_noguard_probe`), so no data was at
  risk. 23 `SAFETY VIOLATION` stops. One test reached the connection step instead:
  ```
  --- FAIL: TestMigrator_PreExistingInvalidRow_ValidationFails (0.01s)
      migrator_test.go:555: failed to connect to test database: failed to connect to `user=postgres database=minicloud_noguard_probe`: 127.0.0.1:5433 (127.0.0.1): server error: FATAL: database "minicloud_noguard_probe" does not exist (SQLSTATE 3D000)
  ```
  **Candidate finding (minor; executed plus confirmed by code reading of
  `internal/storage/postgres/migrator_test.go:546-575`):**
  `TestMigrator_PreExistingInvalidRow_ValidationFails` has no `_test` suffix guard. If
  `MINICLOUD_TEST_DATABASE_URL` pointed at the dev database `minicloud`, it would create
  a `test_migrator_pre_existing_*` schema there, run migrations in it, and drop it.
  Impact is limited to its own schema, but it breaks the guardrail promised in
  `docs/testing-postgres.md`. Suggested fix (out of scope for P0-01: Go code outside
  `tests/docs`): add the same suffix check as `TestMigrator_FreshMigrate`. Not
  registered in `docs/security/findings.md` (owned by P4-00).
- **Secrets:** all command output above has the password redacted. `.env` is ignored
  (`.gitignore:19:.env`) and not staged. The section 9 commands use `docker exec` and
  print no credentials.
- **Not tested:** concurrent `make test-db` runs from both worktrees at the same time
  (Gemini's database is unused so far); the section 9 commands against a stopped
  container.
