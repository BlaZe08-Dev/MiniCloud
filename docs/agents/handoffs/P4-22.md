## SEC-066 (for registration by P4-19): raw database errors in coordinator logs
- Severity: medium (information disclosure to anyone who can read coordinator logs: log shipping, shared terminals, CI artefacts). Evidence label: **executed** (`evidence/repro-red.log`).
- Description: when the database is unreachable, the coordinator logged the full pgx v5 connect error, `failed to connect to \`user=<user> database=<db>\`: <host>:<port> (<host>): <dial detail>`, at WARN from the lease sweeper ("lease sweeper tick failed"), the assignment pass ("assignment pass failed") and the poll-time pass refresh ("assignment pass refresh failed"), and at ERROR from the HTTP path ("database outage or connection failure", "readiness probe failed", "internal server error") and startup ("failed to ping postgres database", "failed to parse database configuration", ...). Cause: `mapPgError` (`internal/storage/postgres/repository.go`) ends in `return err` and about 30 repository paths return `err` raw, so `pgconn.ConnectError` text reaches every caller, and the loop and startup sites logged `err` directly. The API sites used a regex `sanitizeError` that removed IPv4:port and `localhost` but kept `user=` and `database=`, and would have kept a DNS host name such as `db.internal:5432`.
- Scope: not specific to round_robin. The sweeper runs under every policy and was the first line to leak in the reproduction (ticks every 500ms in the rig), so fifo_pull leaked the same way; `make test-outage` LeakScan failing on `:5433` under round_robin was the assignment loop adding more lines in the outage window. That LeakScan passed before on fifo_pull is consistent with timing (no failed tick logged inside the outage), **inferred**, not verified.
- Reproduction without container control: `TestFault_DBOutage_RoundRobin_CoordinatorLogsNoDBDetail` (`tests/faultinject/logleak_test.go`). Real coordinator binary, `MINICLOUD_DISPATCH_POLICY=round_robin`, default assignment interval, database reached only through `sectest.FaultProxy`; `ModeDrop` mid-run. Red on the unfixed tree (commit 6109c4c, `evidence/repro-red.log`), offending line: `{"level":"WARN","msg":"lease sweeper tick failed","err":"failed to connect to \`user=postgres database=minicloud_claude_test\`: 127.0.0.1:42411 (127.0.0.1): failed to receive message: read tcp 127.0.0.1:37568->127.0.0.1:42411: read: connection reset by peer"}`.
- Fix: log boundary, one helper (`internal/logsafe`), see below. Status: fixed on this branch, awaiting audit and the owner's `make test-outage` run.

## Step 1: every log site (full table in `evidence/investigation.md`)

## Step 2: choice and why (log boundary, not source)
A source sentinel is not safe: `isConnectionOrTimeoutError` (`internal/api/handlers.go`) decides 503 versus 500 by `errors.As` on `net.Error` and `*pgconn.PgError` and by substrings of `err.Error()` ("connection refused", "failed to connect", "dial tcp", "closed pool", ...). Removing raw text would turn some outages from 503 into 500, and the worker backs off on 503 (`ErrServiceUnavailable`) but not on 500: a status and retry change, the stop rule. ~30 return paths bypass `mapPgError`, and `internal/coordinator` may not import pgx. The log-boundary helper changes no error value.
`logsafe.Class(err)` returns a label from a closed set (`connection_refused`, `connection_reset`, `connection_closed`, `broken_pipe`, `host_unreachable`, `timeout`, `deadline_exceeded`, `context_canceled`, `dns`, `network`, `tls`, `closed_pool`, `connection_failed`, `invalid_database_config`, `domain_<sentinel>`, `domain_invalid_state_transition`, `sqlstate_<5 chars [0-9A-Z]>`, `sqlstate_invalid`, `unclassified`, `none`); never error text. `logsafe.Err(err)` is `slog.String("err", Class(err))`. Stdlib and `internal/domain` only. The regex `sanitizeError` was removed (no other user).
**Behaviour unchanged (confirmed by code reading of the diff, and executed):** the diff of every production file except `internal/logsafe` touches only `slog` argument lists and imports (`git diff 468229f -- internal/coordinator internal/api cmd`). Executed: `TestLogSafe_APISites_LogClassOnly_StatusUnchanged` asserts 503 (connection error), 503 (readiness), 500 (unmapped); `TestLogSafe_LeaseSweeperTickFailed_LogsClassOnly` asserts `Tick` returns the identical error (grace counting); `TestLogSafe_AssignmentPassFailed_LogsClassOnly` asserts the round still ends after one failed pass; all pre-existing status, grace, sweeper and worker 503 tests pass unchanged (gates below). The one visible log change besides the value: the refresh line's key is now `err` (was `error`).
