## Q3 evidence: what GET /v1/jobs/{id}/attempts really returned
Checked in a real run (own database, one `sha256_loop` job, coordinator and worker started by hand):
`{"attempts":[{"id":"att_job_1_...","job_id":"job_1_...","attempt_no":1,"worker_id":"q3probe-w1","lease_token_hash":"...","state":"COMPLETED","started_at":"2026-11-20T00:25:52.312477+05:30","finished_at":"2026-11-20T00:25:52.416181+05:30","lease_expires_at":"...","exit_code":0,"output":"{...}"}],"job_id":"job_1_..."}`
Both fields are present with microsecond precision, so S3 uses `finished_at - started_at`; no fallback was needed. Observation for the auditor, not changed here: the response carries the `id` key, not `attempt_id` as `docs/protocol.md` section 3.3 shows, and it includes `lease_token_hash` and `output`.

## Deviations and notes
- The own database was at schema version 5 and the coordinator requires 6, so it was migrated once with the existing migrator (`go run ./cmd/migrate`, own database only). `mcbench` itself never migrates.
- Extra flags beyond the ADR text: `-repeats` (S1/S4 recorded repeats, default 3, after one discarded warm-up run), `-warmup` (S2 discarded measurements, default 10), `-task`, `-sleep-ms`, `-iterations`. The started coordinator uses the `-coordinator-url` host and port (default 127.0.0.1:18080).
- S2 forces zero real workers (a probe worker registered over HTTP does the polling).
- S3 submits one job at a time and attributes each run to the worker named on the attempt; it stops when every worker has N recorded runs or at a cap, and notes any shortfall.
- The first S1 run (commit 8473c9a) was discarded because the recorded command line showed a redaction glitch; a second S2 run was discarded because it started at load 0.99 with an untracked output file making `dirty=true`. All four kept results come from a clean tree at `deaa293` after waiting for load below 0.7. `make bench` still accepts load up to 1.0.
- Test names: `TestPercentile_KnownInputs`, `TestSummarize_UnsortedTiesAndSmallN`, `TestSummarize_P95NotMaxAtN20Plus`, `TestCheckIdle`, `TestCheckDatabaseURL`, `TestCheckLoopbackURL`, `TestResult_InvalidWithoutEnvironment`, `TestResult_FormatRoundTrip`, `TestRedact_RemovesCredentials`, `TestSmoke_AllScenariosAgainstFake`.
