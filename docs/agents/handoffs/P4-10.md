## Design decisions and deviations from the design doc (with reasons)
- `MaxPollResponseBytes` value: Set to `executor.MaxPayloadSizeBytes + 64*1024` (128 KiB). The coordinator's maximum allowed task payload is `executor.MaxPayloadSizeBytes` (64 KiB). 64 KiB headroom provides ample space for the assignment JSON wrapper, task type, IDs, lease tokens, and timestamp metadata while strictly bounding memory growth on adversarial streams.
- Zero line numbers in live documentation: In accordance with repository documentation rules, all references in live docs cite function names (e.g. `pollWork`, `renewOnce`, `reportResult`) rather than line numbers.

## Tests added (name, file, what property it guards, mutation proof)
1. `TestPollWork_OversizedResponseRejected` (`internal/worker/hardening_test.go`):
   - Guards: SEC-060. Fake coordinator streams responses larger than `MaxPollResponseBytes` (262 KiB) on both HTTP 200 (assignment) and HTTP 503 (error envelope). Verifies `pollWork` returns an error and reads at most `MaxPollResponseBytes + 1024` bytes.
   - Mutation proof:
     - M1: Removed `io.LimitReader` on assignment decode. Killed by `TestPollWork_OversizedResponseRejected/AssignmentDecode` (read 262244 bytes > 132096 limit). Evidence in `docs/agents/handoffs/P4-10-evidence/M1.txt`.
     - M2: Removed `io.LimitReader` on error-envelope decode. Killed by `TestPollWork_OversizedResponseRejected/ErrorEnvelopeDecode` (read 262197 bytes > 132096 limit). Evidence in `docs/agents/handoffs/P4-10-evidence/M2.txt`.
2. `TestPollWork_MaxLegalAssignmentAccepted` (`internal/worker/hardening_test.go`):
   - Guards: SEC-060. An assignment with the largest legal payload size (`executor.MaxPayloadSizeBytes` = 64 KiB = 65536 bytes) decodes cleanly without truncation.
3. `TestWorker_URLPathEscaping_RenewAndReport` (`internal/worker/hardening_test.go`):
   - Guards: SEC-061. Validates that IDs containing `"../"`, `"?"`, `"#"`, and `"%2f"` reach the fake coordinator as one escaped path segment each in both `renewOnce` (`/v1/jobs/{job_id}/attempts/{attempt_id}/renew`) and `reportResult` (`/v1/jobs/{job_id}/attempts/{attempt_id}/result`).
   - Mutation proof:
     - M3: Removed `url.PathEscape` in `renewOnce`. Killed by `TestWorker_URLPathEscaping_RenewAndReport/RenewOnce` (unescaped paths like `/v1/jobs/..//attempts/att-1/renew` failed). Evidence in `docs/agents/handoffs/P4-10-evidence/M3.txt`.
     - M4: Removed `url.PathEscape` in `reportResult`. Killed by `TestWorker_URLPathEscaping_RenewAndReport/ReportResult` (unescaped paths failed). Evidence in `docs/agents/handoffs/P4-10-evidence/M4.txt`.

## Security review
- Assumptions challenged:
  - Coordinator poll responses can be trusted to be finite: Challenged and rejected. An attacker or corrupted coordinator streaming infinite bytes or an oversized envelope could exhaust worker memory. Solved by bounding responses via `io.LimitReader` and `MaxPollResponseBytes = 128 KiB`.
  - JobID and AttemptID are always benign URL path segments: Challenged and rejected. Special characters (`../`, `?`, `#`, `%2f`) alter URL structure and path hierarchy if interpolated directly. Solved by escaping with `url.PathEscape`.
- Attacks tried:
  - Streaming oversized response body (>262 KiB) during work polling on HTTP 200 (assignment) and HTTP 503 (error envelope): Executed, confirmed bounded to `MaxPollResponseBytes`.
  - URL path traversal via `"../"`, path truncation via `"?"` and `"#"`, and percent-encoding ambiguity via `"%2f"`: Executed, confirmed preserved and escaped as single path segments.
- Not tested:
  - Network-layer TCP packet fragmentation across multiple physical machines (deferred to V3).
- Findings:
  - SEC-060: Fixed (executed).
  - SEC-061: Fixed (executed).
