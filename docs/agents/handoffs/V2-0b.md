## What changed (by package)
- `internal/domain`: `EffectiveWorkerSlots` removed. New `MaxReservationsPerWorker = 8`, `AssignableSlots(executesConcurrently, totalSlots)` (`totalSlots` if declared, else 1), `CanReserve(assignable, active, reserved)` (`active+reserved < assignable && reserved < 8`), `HasFallbackRoom` (the same sum, no cap). `Worker.ExecutesConcurrently` (JSON `executes_concurrently`).
- `internal/storage` (in memory): `eligibleWorkersLocked` uses `CanReserve` with a per-decision count of live reservations (`liveReservationsLocked`, formerly a boolean). `ClaimForPoll` fallback arms check `HasFallbackRoom` and return `ErrWorkerNoCapacity` when it fails. `UpsertWorker` already copies the whole struct, so the field is stored and reset by re-registration.
- `internal/storage/postgres`: migration `000006_worker_executes_concurrently.sql` (`BOOLEAN NOT NULL DEFAULT FALSE`). The pass snapshot (`assignChooseWorker`) and the re-check under the worker row lock (`assignLockAndRecheck`) both use the new predicate, written out twice: the repository's SQL-safety test (`security_test.go`) rejects SQL built by string concatenation. `claimTx` reads `executes_concurrently` under the worker row lock and, for fallback claims only, counts live reservations and applies `HasFallbackRoom`. `UpsertWorker` writes the column on insert and on conflict; `GetWorker` and `ListWorkers` read it with a subquery (the `worker_capacity` view is unchanged).
- `internal/worker`: `register` sends `"executes_concurrently": true`.
- `internal/api`, `internal/coordinator`: no production change. The field reaches the repository because the register body is decoded into `domain.Worker`.
- Tests: see below. `tests/security-tests.list` gains the five new fault and abuse test names (the `make test-security` false-green guard).
- Docs: ADR-0020 (Accepted, decisions, deviations), ADR-0017 amendment notes (Section 2.4, INV-10, Q5, Section 6.2 with the SEC-016 to SEC-015 correction), `docs/security/findings.md` (SEC-015 update, new SEC-068), `docs/fault-injection-plan.md` (FS-25 to FS-28), `docs/protocol.md` (register field), `docs/schema.md` (migration 000006), README, CHANGELOG [Unreleased], PROJECT_STATE, TASKS (status, migration 000006 taken, V2-1 moves to 000007, the Q8 candidate line), and the 000006-to-000007 lines in `docs/roadmap.md`, `docs/post-v1/ROADMAP.md`, `docs/post-v1/IMPLEMENTATION_PLAN.md`, `docs/post-v1/ARCHITECTURE.md`, `docs/post-v1/WORKFLOW_MODEL.md`.

## Design decisions and deviations from the design doc (with reasons)
Orchestrator decisions Q1 to Q8 are recorded as Decided in the ADR-0020 Status section. Deviations (also listed there):
1. `TestReservationCap_FitsAcceptWindow` is in `internal/worker/real_slots_test.go`, not `internal/coordinator`: the existing timing test `TestPollTiming_AcceptWindowExceedsBackoff` is in `internal/worker`, and that package can import both constants.
2. `TestMigrator_Migration000005_FreshSchema` asserted that 000005 is the **last** migration, so it failed once 000006 existed (executed: "expected the fifth and last embedded migration to be 000005_assignment_round_robin.sql, got 6 migrations"). It now applies only the first five migrations (through the existing helper `migrationsUpTo`) and checks the same schema objects. The last-migration pin moved to `TestMigrator_Migration000006_FreshSchema`. Nothing is weakened: every assertion stays, and the pin still exists.
3. The PostgreSQL predicate is duplicated in two SQL literals instead of one shared constant (the SQL-safety test failed on the shared-constant version: "assignment.go:383: Query query argument uses string concatenation (+)"). Mutant M8 shows the re-check copy is tested independently.
4. The INV-10 tests keep their names (`TestConformance_Assign_OneReservationPerWorker`, `TestConformance_Assign_SkipsWorkerWithRunningAttempt`), as the ADR planned; they register undeclared workers, so they now guard the one-slot behaviour of old workers. Their code is unchanged.

## Security review
- **Assumptions challenged:** an unauthenticated client sets `executes_concurrently` and `total_slots = 1024` (SEC-068, Low, within SEC-004); covered by `TestAbuse_Register_LargeDeclaredSlots_ReservationCap` and `TestConformance_Assign_ReservationCapPerWorker`. A non-boolean field gives 400 `MALFORMED_JSON` (`TestAbuse_Register_ExecutesConcurrentlyNotBoolean_400`). A fallback claim cannot push active + reserved above the slots (`TestConformance_Claim_FallbackRespectsReservedSlots`). The re-check under the row lock cannot be bypassed by a concurrent claim (`TestPostgresRepository_Assign_RecheckUsesSlotRule`). Re-registration with fewer slots cannot gain reservations (FS-28).
- **Attacks tried that held:** a reservation to a locally full worker (FS-26) lapses once and stops; a multi-reservation worker that dies is revoked without lapses (FS-25); old worker with new coordinator, and new worker with old coordinator (runs 5, 7, 8; FS-27).
- **Not tested:** worker authentication (SEC-004, V3-2); several coordinators; burst timing under deep backlog.
- **Findings:** SEC-068 (Low, Open within SEC-004; executed). No other finding. The SEC-016 citation for `total_slots` in ADR-0017 Section 6.2 was a numbering slip and is corrected to SEC-015 (confirmed by code reading of `docs/security/findings.md`).
