Design decisions and deviations from the design doc (with reasons):
- **Selective Subshell Export**: In PostgreSQL mode, commands use `( export MINICLOUD_DATABASE_URL="$(grep -E '^MINICLOUD_DATABASE_URL=' .env | cut -d= -f2-)"; ... )` inside subshells. This ensures that `MINICLOUD_TEST_DATABASE_URL` is never exported, passwords containing `&` or special characters are safely preserved, and no environment variables leak into the parent interactive shell.
- **In-Memory Quick Start Order and Readiness**: The quick start explicitly specifies startup order, adds readiness polling against `/readyz`, and clarifies that `mc` commands should be issued after the worker registers.
- **Port Isolation**: Quickstart verification was performed on free port 18080 to prevent collisions with any existing daemon on port 8080.
- **Strict Formatting Constraints**: No badges, no screenshots, no marketing claims, no emojis, no line-number citations.

- End-to-end Quick Start execution on port 18080:
The quickstart was run by extracting all fenced `bash` blocks under "In-Memory Mode" from `README.md` with `awk` and substituting port `8080` to `18080` with `sed`.
The test script is not committed to the repository; its exact text is reproduced here:

```bash
#!/usr/bin/env bash
set -e

REPO_DIR="/home/blazeee/MiniCloud-gemini"
SCRATCH_DIR=$(mktemp -d)
PORT="18080"

trap 'rm -rf "$SCRATCH_DIR"' EXIT

echo "=== Extracting fenced bash blocks from README.md ==="
awk '/### 1\. In-Memory Mode/,/### 2\. PostgreSQL Mode/ {
  if ($0 ~ /^```bash/) { in_block=1; block_num++; next }
  if ($0 ~ /^```/ && in_block) { in_block=0; next }
  if (in_block) { print > (scratch "/block" block_num ".sh") }
}' scratch="$SCRATCH_DIR" "$REPO_DIR/README.md"

for f in "$SCRATCH_DIR"/block*.sh; do
  sed -i "s/8080/$PORT/g" "$f"
done

cd "$REPO_DIR"

echo "=== Block 1: make build ==="
bash "$SCRATCH_DIR/block1.sh"

echo "=== Block 2: Start coordinator in background (port $PORT) ==="
bash "$SCRATCH_DIR/block2.sh" > "$SCRATCH_DIR/coordinator.log" 2>&1 &
COORD_PID=$!
echo "Coordinator started with PID: $COORD_PID"

cleanup() {
  echo "=== Cleanup: stopping coordinator (PID $COORD_PID) and worker (PID ${WORKER_PID:-none}) ==="
  if [ -n "$WORKER_PID" ] && kill -0 "$WORKER_PID" 2>/dev/null; then
    kill "$WORKER_PID" 2>/dev/null || true
    wait "$WORKER_PID" 2>/dev/null || true
  fi
  if [ -n "$COORD_PID" ] && kill -0 "$COORD_PID" 2>/dev/null; then
    kill "$COORD_PID" 2>/dev/null || true
    wait "$COORD_PID" 2>/dev/null || true
  fi
  echo "Processes stopped."
}
trap cleanup EXIT

echo "=== Block 3: Readiness check (probe) ==="
timeout 20 bash "$SCRATCH_DIR/block3.sh"
echo "Coordinator readiness probe succeeded."

echo "=== Block 4: Start worker in background ==="
bash "$SCRATCH_DIR/block4.sh" > "$SCRATCH_DIR/worker.log" 2>&1 &
WORKER_PID=$!
echo "Worker started with PID: $WORKER_PID"

echo "=== Waiting for worker registration ==="
timeout 10 bash -c "until grep -q 'worker successfully registered with coordinator' '$SCRATCH_DIR/worker.log' 2>/dev/null; do sleep 0.2; done"
echo "Worker registered successfully."

export MINICLOUD_COORDINATOR_URL="http://127.0.0.1:$PORT"

echo "=== Block 5: ./bin/mc workers ==="
bash "$SCRATCH_DIR/block5.sh"

echo "=== Block 6: ./bin/mc submit ==="
SUBMIT_OUT=$(bash "$SCRATCH_DIR/block6.sh")
echo "$SUBMIT_OUT"
JOB_ID=$(echo "$SUBMIT_OUT" | awk '/ID:/ {print $2; exit}')
echo "Extracted job_id: $JOB_ID"

echo "=== Block 7: Immediate query (state may be QUEUED or RUNNING) ==="
sed "s/<job_id>/$JOB_ID/g" "$SCRATCH_DIR/block7.sh" | bash

echo "=== Waiting about a second for worker to execute job ==="
sleep 1.2

echo "=== Block 7: Query after completion ==="
sed "s/<job_id>/$JOB_ID/g" "$SCRATCH_DIR/block7.sh" | bash

echo "=== Block 8: Inspect attempt execution history ==="
sed "s/<job_id>/$JOB_ID/g" "$SCRATCH_DIR/block8.sh" | bash

echo "=== Quickstart execution finished successfully ==="
```

What this helper script adds beyond the literal README text:
1. Automated extraction of the eight fenced `bash` blocks into separate scripts (`block1.sh` through `block8.sh`).
2. Port parameterization: replacing `8080` with `18080` across extracted command files to avoid port collision.
3. Backgrounding coordinator and worker with recorded PIDs (`$!`) and output logging.
4. Guaranteed cleanup trap to kill recorded child PIDs (`kill "$WORKER_PID"`, `kill "$COORD_PID"`).
5. Waiting for worker registration via log grep (`worker successfully registered with coordinator`).
6. Exporting `MINICLOUD_COORDINATOR_URL="http://127.0.0.1:18080"` for `mc` commands in Terminal 3 (as advised in README port-busy section).
7. Extracting generated `job_id` from `mc submit` output to substitute for `<job_id>` in subsequent `mc get` and `mc attempts` commands.
8. A 1.2-second sleep corresponding to README's "Wait about a second for the worker to pick the job up".
