ORCHESTRATOR DECISIONS FOR V2-1-ADR (owner answers, 2026-11-20)

OD-19 DECIDED by the owner: option C.
- Node identity is a random UUID generated by the node on first start and persisted in a file with mode 0600 in a directory the node owns. The same UUID is reused on every restart.
- The coordinator validates the format. Node registration is idempotent: the same ID registering again updates the existing row and never creates a second one.
- A separate display_name is an operator-configurable label. It is NOT unique and NOT a key and has no meaning for scheduling.
- V3-2 later binds the UUID to an authenticated enrollment by adding a credential column; V2-1 must not need to change for that.
- Known limit, state it plainly in the ADR: until V3-2, any caller who knows an ID can impersonate that node (consistent with SEC-004). Do not claim this is solved. Log it as a finding or extend SEC-004 as appropriate.
- Rejected: configured-only ID (collisions, typos), hardware-derived ID such as machine-id (breaks on cloned VMs, leaks a machine identifier).

OD-08 DECIDED by the owner (option A, with additions): Linux is the first supported implementation, not the exclusive target.
- MiniCloud must be architected for Windows, Linux and macOS compatibility.
- Use a versioned, OS-independent capability contract. Isolate OS-specific functionality behind platform adapters.
- Implement and promise only Linux in V2-1. On other platforms a field reports unknown, never an invented value. The ADR must show where the adapter boundary sits and how a Windows or macOS adapter would be added without changing the contract.

OD-09 DECIDED by the owner (option A, with additions): scheduler-side node-level resource reservations.
- Resources (CPU, RAM, disk, GPU) belong to the node and are shared by its workers; slots belong to the worker.
- Telemetry alone must never guarantee resource availability. Stale telemetry is never used as a hard guarantee.
- Reservations must be atomic (no two assignments can both reserve the same capacity).
- Reservations must be released or reconciled after job completion, failure, cancellation and lease expiry. The ADR must cover each of these four paths, plus coordinator restart (what happens to reservations then), and name the tests that prove each one.

STILL OPEN (do not answer them): OD-20 workers per node (before V3-3); OD-21, OD-22, OD-23 (TTL values), OD-24, OD-25; coordinator availability model and target scale.
