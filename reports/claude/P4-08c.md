## Finding (break before fix; not fixed)

**F-5b-1 (minor, executed).** `Service.SubmitJob` stamps `jobs.created_at` with the coordinator's process clock, and PostgreSQL stores that value. The age arm then compares it with `clock_timestamp()`. When the test's process clock was about 11 minutes ahead of the database clock, `TestPoll_RateLimitedPoll_NoAgeClaim` and `TestFault_AssignmentPassStalled_JobRunsWithinBound` could never make an age claim (`P4-08c-evidence/finding-created-at-process-clock.log`). The tests now start the process clock at database time; the production code is unchanged. Suggested fix, for the orchestrator to decide: have PostgreSQL stamp `created_at` itself. I did not enter it in `docs/security/findings.md`, which this task does not own.
