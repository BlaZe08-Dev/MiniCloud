## Finding (break before fix; not fixed)
**F-5c2-1, major, executed, pre-existing on main.** `ComputeBackoffWithJitter` shifts `1 << (failureCount-1)`. From 64 consecutive failures on it returns 0 s (`probe-backoff-overflow.log`). After 64 failed polls in an outage, every worker polls with no sleep. Renewal and delivery call the same function (code reading; not tested). Suggested fix: clamp the count before the shift, and add a test that the backoff stays at least half the cap. Register entry: for the owner of `docs/security/findings.md`.
For the register, informational (inferred): `assigned_worker_id` on the unauthenticated job view makes a reservation target easier to pick. It adds no capability (SEC-004).
