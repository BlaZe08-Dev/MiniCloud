## 7. Beyond the ADR (for an ADR amendment)

1. **Publication is `os.Link` only** (C1). ADR Section 5 says "an exclusive link or rename that fails if it exists". `os.Rename` replaces the destination on Linux and Windows, so a rename that fails if the name exists does not exist in the standard library. Hard links unsupported means a clear error with no fallback (`nodeid.go:249-259`).
2. **Existing directory is inspected, never chmodded** (C2): refused on symlink, non-directory, any group or other bit (`mode & 0077`), or (unix) a different owner. ADR Section 5 only names the 0700 mode.
3. **A newly created directory is chmodded to exactly 0700 after `os.Mkdir`**; missing parents are created 0700 and not chmodded (`nodeid.go:122-155`). Known edge: a umask that removes the owner's write bit (for example 0277) makes parent creation fail with a clear error; only the existing-parent case is tested.
4. **The ID file is written as the UUID plus one newline**; on read, one trailing newline is accepted, and at most 37 bytes are read; anything else is invalid content.
5. **Directory fsync after publication**; an `EINVAL` from a filesystem that cannot fsync a directory is tolerated, any other error is returned (`nodeid_unix.go:48-58`).
6. **A failure to remove the temp file after a successful publish returns an error** even though the ID is published (`nodeid.go:228`), because a stray hard link is a defect worth surfacing; the next start still reads the published file.
7. **`NewProbe(stateDir string) Probe`** is the production constructor (ADR 6.2 gives only the interface). ADR 6.3 needs the state directory for the disk fields and the interface has no parameter, so the directory is a constructor argument. `""` leaves disk fields nil.
8. **Injectable root**: the probe reads `<root>/proc/...` and `<root>/sys/fs/cgroup/...`; production root is `/`.
9. **Probe details not stated in the ADR**: `cpu_model` replaces bytes outside printable ASCII with `?`, trims and truncates to 128; physical cores count only blocks that carry both `physical id` and `core id`; a cgroup limit only lowers a known `MemTotal` (never sets one when `/proc/meminfo` is unreadable) and a value above 2^53-1 counts as no limit; available memory is lowered only when `MemAvailable` is known; disk free uses `Bavail` (what an unprivileged process can use), not `Bfree`; a canceled context returns the context error (a per-field read error returns nil for that field, per ADR Section 10).
10. **Domain**: telemetry numbers are `*int64`; `cpu_*` cores are validated `>= 1` and `gpu_count >= 0` as in Section 9; `FormatNodeID` is a pure function so `crypto/rand` stays in `internal/platform`; `ValidateSessionID` reuses the node ID rule; extra types `NodeRegistration` and `NodeTelemetryReport` (embedded `NodeTelemetry` so the JSON is flat).
11. **`LoadOrCreateNodeID` does not require an absolute path.** ADR 4.5 requires `MINICLOUD_NODE_STATE_DIR` to be absolute; that belongs to the config in V2-1d. An empty path is refused, never defaulted.
12. **Architecture test** also walks subpackages of storage and api (`packageDirs`, `boundaries_test.go`), and asserts the platform package still imports domain.
13. **Two mutants of my own (X1, X2)** beyond the requested list.

## 8. ADR gaps found (listed, not fixed)

- **G1** ADR Section 5 "an exclusive link or rename that fails if it exists": not possible for rename (see Beyond item 1). Suggest amending to "exclusive link".
- **G2** ADR 6.2 `Probe` has no way to pass the state directory that ADR 3.2 and 6.3 need for the disk fields (Beyond item 7).
- **G3** ADR 6.3 reads cgroup v2 limits, but the ADR names no path. This probe reads `/sys/fs/cgroup/memory.max`, which is right inside a container with its own cgroup namespace. A process in a nested cgroup that is not namespaced (for example a systemd service on the host) has its limit under `/sys/fs/cgroup/<path from /proc/self/cgroup>/memory.max`, which this probe does not read, so threat T8 is only partly covered. **confirmed by code reading, not run.**
- **G4** The ADR 14.1 text for `TestNodeIDFile_DirectoryUnwritable_Refuses` says "no registration is sent". This slice sends nothing, so that clause belongs to the worker slice V2-1d; here the test proves only that no `node_id` or temp file exists afterwards.
- **G5** ADR Section 5 says wide mode is refused "(Linux adapter)". The checks live in `//go:build unix` files, so they also apply on macOS and the BSDs, which are untested.
- **G6** ADR Section 9 gives `os` and `arch` as `^[a-z0-9_]{1,32}$`; `runtime.GOOS` and `GOARCH` fit today, but the ADR does not say what a future value outside that set should do (registration would be rejected).
