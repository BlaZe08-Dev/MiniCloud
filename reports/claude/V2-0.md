**A-1.** New test `TestConcurrency_RunWaitsForHeartbeatGoroutine` in `internal/worker/concurrency_test.go`, based on the audit's idea. It holds the heartbeat goroutine inside its log call, cancels, and fails if `Run` returns before that goroutine finishes. It kills mutant e (`mutants.log`).

**A-2.** Panics are now recovered in three agent goroutines in `internal/worker/client.go`, each in the fail-safe direction:
- Renewal goroutine: the lease is treated as lost. `markLost` and `cancelTask` run, the result is dropped, and the slot is freed through the normal `runAttempt` release.
- Delivery-budget goroutine: delivery expires at once (`expired` is set and the delivery context is cancelled).
- Heartbeat goroutine: the recover is per tick, in the new `heartbeatTick`, so the panic is logged and the loop continues.

Each writes one ERROR line, "agent goroutine panicked; recovered", with only `goroutine`, `job_id`/`attempt_id` (for the two per-attempt goroutines) and `panic_type`. Nothing else in the worker's behaviour changed.

New tests:
- `TestConcurrency_RenewalPanicTreatsLeaseAsLost`: the fake clock's `NewTimer` panics once.
- `TestConcurrency_DeliveryBudgetPanicExpiresDelivery`: the budget timer's `C` panics once, and the clock is never advanced.
- `TestConcurrency_HeartbeatPanicIsRecovered`: the log handler panics in the heartbeat path, because the heartbeat uses `time.Ticker` and not the agent `Clock`.

Each test shows a concurrent attempt surviving and the slot count staying exact, and checks that the log never contains the panic value or the lease tokens.

## Final message

V2-0 Stage B is built and pushed on `agent/claude/V2-0` (work tip 114c984). All the gates I ran passed with the baseline counts plus my new tests. ADR-0019 is now Accepted.

**What changed**
- The worker now runs up to `MINICLOUD_WORKER_SLOTS` attempts at once. It takes a slot before each poll, so a full worker never polls.
- Each attempt releases its slot exactly once, in one `defer`. A task panic is caught and logged with its type only. No result is reported and the lease expires.
- Register and heartbeat now report free slots live.
- Shutdown waits at most `ResultDeliveryBudget` (60 s) for running attempts.
- `MINICLOUD_WORKER_SLOTS` is limited to 1 to 1024, checked against `coordinator.MaxWorkerSlots`.
- `ExecuteAndReport`, backoff, `pollSleep` and the `Clock` seam are unchanged.
- Docs: README, CHANGELOG, PROJECT_STATE, CURRENT_BASELINE, roadmap and TASKS are updated. README and CHANGELOG say that under `round_robin` parallelism stays one job per worker until V2-0b. V2-0b and O1 are on the task board, and ADR-0017 has a Q5 note.
