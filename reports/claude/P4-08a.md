**Key decisions (all in ADR-0017, with reasons and rejected alternatives):**
1. Assignment is three nullable columns on `jobs` plus a lapse counter, with a CHECK that ties them to `QUEUED`/`RETRYING`. No new job state and no new attempt state. Rejected: an `ASSIGNED` state, an assignments table, and a `PENDING` attempt at assignment.
2. Assignment only reserves. The attempt, its number, token and lease are created at claim (the poll), as today.
3. A separate coordinator assignment pass chooses workers. Choosing inside the poll is Candidate B, which ADR-0011 rejected.
4. Round-robin is "next eligible worker by ID after the last assigned worker, wrapping". The cursor is a singleton row written in the pass transaction, so it survives restarts. An index-based rotation (the existing `RoundRobinScheduler`) skews on join and leave.
5. Eligibility needs a healthy status, a fresh heartbeat, and a fresh **poll** (`last_poll_at`). The poll check matters because a worker polls only when idle (`Run` in `internal/worker/client.go` executes synchronously). Free slots are counted net of reservations.
6. Only the assigned worker can claim, and only while the assignment has not expired on database time. Poll never claims unassigned work, except a bounded fallback.
7. Accept window: `MINICLOUD_ASSIGNMENT_ACCEPT_WINDOW`, default 5 s, range 2 to 30 s. A lapse does not consume `max_attempts`. Lapses are counted per job. After `MINICLOUD_ASSIGNMENT_MAX_LAPSES` (default 3) the job becomes fallback-claimable. This bounds the poison-by-lapse loop, which `max_attempts` alone does not bound.
8. Grace suppresses lapse counting but not revocation.
9. Concurrency: correct by the service mutex and row locks with one coordinator. The design relies on the database alone for several coordinators, with a transaction advisory lock so only one pass runs at a time. Lock order follows ADR-0013 and ADR-0014.
10. Protocol changes are additive only: a `policy` field on the poll assignment, and assignment fields on the job view. No new endpoint or error code.
11. `fifo_pull` stays selectable. `DispatchNextJob` gains one clause that clears the new columns, which is a no-op when they are NULL.

**Open questions for the orchestrator** (ADR-0017 Section 8, each with a recommendation):
- Q1: when `round_robin` becomes the default policy (recommend: after slice 5c is green and audited, with owner sign-off).
- Q2: after the lapse limit, fall back to first-poller-wins, or keep reassigning (recommend: fall back, `L = 3`).
- Q3: should a claim whose response is lost consume `max_attempts` (recommend: yes for now; the alternative needs stored tokens, which ADR-0011 forbids).
- Q4: accept window 5 s, range 2 to 30 s (recommend: accept).
- Q5: the worker poll loop is synchronous, so a worker runs one job at a time whatever its `total_slots` (recommend: keep for V1, schedule a worker-concurrency slice before V2 benchmarking).
- Q6: should `RETRYING` jobs be assigned round-robin too (recommend: yes).
- Q7: is the round-robin guarantee per task type (recommend: yes, as written).
- Q8: `chk_jobs_state` omits `REJECTED`, which the domain defines. Fix in `000005` or in a separate task? I did not verify whether any path persists `REJECTED`.
- Q9: must V1 support several coordinators (recommend: not for V1; the design is database-safe but makes no tested claim).
- Q10: approve the new public fields (`assigned_worker_id`, `assignment_expires_at`, `assignment_lapses`) and the poll `policy` field.
- Q11: keep `DRAINING` out of V1 scope (recommend: yes).

**Limits of the design.** Nothing is measured: no pass latency, no write cost for `last_poll_at`, no distribution under load. No test in the ADR exists yet; every test name is marked `(planned test)`. Fairness is over decisions and per task type, not over executions or slots. Workers and clients are unauthenticated (SEC-004, accepted), so the sybil case is not defended. Multi-coordinator operation is designed for but not claimed. A lost claim response costs one lease period and one attempt. Pre-existing gaps are recorded, not fixed: the `REJECTED` CHECK gap (Q8), the tie-order difference between memory and Postgres (insertion order versus `created_at, id`), and the synchronous worker loop (Q5).
