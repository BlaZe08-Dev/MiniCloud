## Beyond the ADR
D1 display_name always "", agent_version version.Version, contract_version domain.ContractVersion.
D2 One synchronous node registration before the first worker registration; later node calls in one background goroutine; loop and heartbeat never wait.
D3 Outcomes of POST /v1/nodes/register: 200 attached; 429 RATE_LIMITED attached plus one re-send after Retry-After (absent/invalid/negative 60 s placeholder, cap 24 h); 404, any 400, 429 NODE_LIMIT_REACHED legacy for life; 5xx/transport/other detached, retry after ComputeBackoffWithJitter(failures, 1 s, 30 s) (constants nodeBackoffBase/Max).
D4 node_id key only while attached; otherwise body identical to origin/main.
D5 Worker register 400 while carrying node_id: one register without it, detach, wake node goroutine; never a loop.
D6 Telemetry rules as in the table above; one at a time; seq +1 per attempt; failed report never resent; sample_age_ms from monotonic time.
D7 Interval unset: registrations and 429 re-send only, one info line.
D8 Node goroutine owns session/seq/failures/legacy; attached ID in an atomic pointer; waits only on a.clock timers and a wake channel; recovers per tick; Run waits for it.
D9 State dir resolution then LoadOrCreateNodeID then NewProbe before any request; any error returned by Run.
D10 Reporting off: none of D9 runs; one warning naming both settings if the state dir is set.
D11 No hardware/telemetry value, session_id or state dir path in logs (except the D9 startup error); coordinator codes logged as the code only.
D12 Node response bodies read through io.LimitReader(64 KiB) and closed.
My own choices, beyond D1 to D12:
- Retry-After "0" is floored to 1 s (minRetryAfter) so a 429 cannot spin; D3 does not say.
- The first telemetry report is sent right after attach, not after one interval (D6 says "one per interval").
- Error codes from the coordinator are logged only if they look like codes (A-Z, 0-9, _, max 64 bytes), else empty (safeCode).
- After a D5 fallback inside the node goroutine's own re-attach, the goroutine drains the wake and backs off (nodeBackoff) instead of retrying at once, otherwise a coordinator that keeps rejecting node_id would loop; the first fallback is still immediate.
- A failed re-send of the node registration while attached (5xx, transport) keeps the worker attached and re-sends after backoff; a 404/400 on the re-send goes legacy and re-registers the worker without node_id. D3 does not cover these.
- Telemetry statuses not listed in D6 (other 4xx, 409 with another code) are treated like 5xx. A failed probe.Telemetry skips that report without consuming a seq. If a new session_id cannot be drawn after a 409, the old session is kept.
- Config error for a relative state dir names the key but not the value (D11 spirit).
- LoadWorkerConfig leaves the interval at 0 for unset/empty before calling the shared positive-duration helper, which would otherwise reject its own default (a bug my config test caught).
- Test-only: SetProbeFactoryForTest, SetHTTPTimeoutForTest; the 429 and legacy tests run with an unset interval where telemetry would add noise.
