## 7. Beyond the ADR (every decision not written in ADR-0022)

1. **ContentHash excludes `agent_version` and `contract_version`** (orchestrator decision, as the task says). Tested by `TestDomain_NodeHardwareContentHash_VersionsNotHashed` and, through the repositories, by the agent-only change in `RunNodeHardwareVersionOnChangeOnlyConformance` (nodes.go:221).
2. **K1 to K7 clarifications** are implemented as written (encoding, FK mapping by exact name, pure `HardwareUpdateLimit`, session rule, parity, migration safety).
3. **The repositories validate their input** (`reg.Validate()`, `report.Validate()`) and return `ErrInvalidRequest` before touching storage, in both implementations, so a repository never depends on the handler having validated. The ADR says validation has already passed in the handler; this is defence in depth and keeps both repositories identical.
4. **`last_seen_at` refresh on an unchanged hash reuses `HardwareUpdateLimit`** (refresh when `elapsed >= interval`; a clock that moved back means no refresh). The ADR says "older than the interval" without a boundary.
5. **`chk_nodes_display_name` and `chk_node_hardware_agent_version` also check `octet_length <= 64`.** ADR Section 9 caps both in bytes, but `VARCHAR(64)` counts characters; the ADR gives the exact CHECK text only for `display_name` (control characters), none for `agent_version`. The additions make the database enforce the same byte limit as the domain. Tested with 33 two-byte characters (`TestSchemaInvariants_NodeChecks`).
6. **Telemetry 23503 defence in depth** is mapped by the exact name `node_telemetry_node_id_fkey` (nodes.go:191), not through `mapPgError`, so `mapPgError` still maps only `fk_workers_node`.
7. **Read model.** `NodeHardwareView` carries `contract_version`, `agent_version` and `reported_at` besides `version` (the ADR lists agent_version among full-view fields); it carries no `content_hash`. `WorkerIDs` is an empty slice, not nil. `ListNodes` is ordered by node ID. PostgreSQL reads one consistent snapshot (read-only REPEATABLE READ).
8. **`RetryAfter` is a `time.Duration`** of whole seconds, plus `RetryAfterSeconds() int` for the header the API slice will write.
9. **A new node's `created_at` and first `last_seen_at`** are `clock_timestamp()` at the insert, then `last_seen_at` becomes the single lock-time value; the in-memory repository uses one clock reading.
10. **`minInterval` 0 is accepted by the repositories** (no limit); the coordinator setting stays "validated positive" (V2-1c). Two concurrency tests use 0 so every change is accepted without sleeping.
11. **The node view omits the "sample age before created_at" rule**: ADR Section 9 marks it "handler only", so neither repository enforces it.
12. **`MapPgError`** is exported to the external tests through a test-only file (`internal/storage/postgres/export_test.go`), and `NodeRawForTest` through `internal/storage/inmemory_export_test.go`, so the suite can compare raw stored state; neither exists in production code.

## 8. Gaps found

1. **Interim API exposure until V2-1c (executed).** A throwaway in-memory API test (deleted, not committed) posted `{"id":"w1",...,"node_id":"3f1c9a2e-6b7d-4e21-9c4a-0d5e8f7a1b23"}` to `/v1/workers/register` and got `500 {"error":{"code":"INTERNAL_ERROR",...}}`. Cause (confirmed by code reading): the handler decodes straight into `domain.Worker` (`internal/api/handlers.go:289-293`), `UpsertWorker` now returns `ErrNodeNotFound`, and `mapDomainErrorToHTTP` has no case for it, so it reaches the default 500 (`handlers.go:148-154`). Also, a registered node's `node_id` would be stored and shown by `GET /v1/workers` regardless of the local-only rule. In practice no node exists before V2-1c (no route creates one), so every `node_id` is unknown. It was forced by the task's design (the `Worker.NodeID` field with a JSON tag, and `api` is out of scope). **V2-1c must map `ErrNodeNotFound` to 400 `INVALID_REQUEST` for worker registration and gate `node_id` on the local-only flag; if V2-1b merges alone, a client can trigger logged 500s.**
2. **K4, known weakness for the ADR amendment (executed, `TestConformance_Node_Telemetry_OlderSessionAfterNewerIsAccepted`).** A report from an older session that arrives after a newer session's report has a different `session_id`, so it is accepted and replaces the stored sample, and the live session's next report is then accepted again for the same reason. This is the ADR 3.3 rule working as written (threat T11 notes the same class). I invented no new transition rule.
