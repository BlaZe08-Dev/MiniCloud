# MiniCloud P4-07 Final Report: CLI Terminal Output Sanitization (SEC-048)

## 1. Summary of Changes by File

- `cmd/mc/sanitize.go`:
  - Implemented `func sanitize(s string) string` to sanitize arbitrary text before terminal display.
  - Normalizes `\r\n` (CRLF) to standard `\n` (LF) to preserve legitimate multi-line formatting.
  - Replaces lone `\r` with literal visible `\r` (`\x5c\x72`) to prevent line-clearing terminal overwrites.
  - Preserves standard printable characters, horizontal tab (`\t`), and newline (`\n`).
  - Replaces all ASCII control codes (C0, DEL) and C1 control characters (`U+0080`..`U+009F`) with visible escape representations (`\x..` or `\u....`), neutralizing ANSI escape sequences, cursor manipulation, screen clearing, OSC hyperlinks, and title rewriting.
  - Optimized with zero allocations when no control characters are present.

- `cmd/mc/sanitize_test.go`:
  - Implemented table-driven unit tests (`TestSanitize`) verifying clean pass-through, ANSI color/reset sequences, CSI cursor manipulation, OSC title manipulation, alternate screen buffer switching, CRLF normalization, lone CR neutralization, DEL (`\x7f`), C1 control characters (NEL, CSI, APC), multi-byte UTF-8 preservation, and tab/newline preservation.
  - Implemented `TestSanitize_VeryLongText` validating 65 KiB payloads containing interspersed control characters.

- `cmd/mc/main.go`:
  - Sanitized worker- and task-supplied output fields in `handleGet`: `job.Result.Output`, `job.Result.Error`, and `job.TaskType`.
  - Sanitized attempt worker ID in `handleAttempts`: `att.WorkerID`.
  - Sanitized worker IDs and supported tasks in `handleWorkers`: `worker.ID` and `worker.SupportedTasks`.
  - Sanitized task type in `handleSubmit`: `job.TaskType`.

- `cmd/mc/failure.go`:
  - Sanitized attempt error message in `failureSummary`: `sanitize(last.Error)`.

- `cmd/mc/failure_test.go`:
  - Added subtest `TestFailureSummary/hostile_error_text_is_sanitized_in_failure_summary` verifying that hostile control sequences embedded in attempt errors are neutralized into visible escape representations.

- `tests/abuse/resources_test.go`:
  - Un-skipped adversarial test `TestAbuse_MCOutput_HostileErrorText`.
  - Parameterized test execution across memory and PostgreSQL backends using `sectest.EachBackend`.
  - Added coverage verifying that hostile ANSI sequences in both `job.Result.Error` (printed to stderr) and `job.Result.Output` (printed to stdout) are escaped into visible literal representations by `mc get`.

- `docs/security/findings.md`:
