# P4-10 Report: Worker Response Body Limit and URL Path Escaping (SEC-060, SEC-061)

## Summary of Changes
1. **SEC-060 (Response Body Size Limit)**:
   - Defined `MaxPollResponseBytes = executor.MaxPayloadSizeBytes + 64*1024` (128 KiB / 131,072 bytes) in `internal/worker/client.go`, setting the poll limit above `executor.MaxPayloadSizeBytes` (64 KiB, the coordinator's maximum task payload) with 64 KiB of headroom for the JSON wrapper and assignment metadata.
   - Bounded coordinator HTTP response body decoding in `internal/worker/client.go` func `pollWork` by wrapping `resp.Body` in `io.LimitReader(resp.Body, MaxPollResponseBytes)` for both the HTTP 503 error-envelope decode and HTTP 200 assignment decode. Added check ensuring an empty assignment (`res.Assignment == nil`) on HTTP 200 returns an explicit error.
2. **SEC-061 (URL Path Parameter Escaping)**:
   - Updated `internal/worker/client.go` func `renewOnce` and func `reportResult` to escape `JobID` and `AttemptID` path parameters using `url.PathEscape`. Imported `"net/url"`.
3. **Tests Added** (`internal/worker/hardening_test.go`):
   - `TestPollWork_OversizedResponseRejected`: fake coordinator streams bodies larger than `MaxPollResponseBytes` (262 KiB); verifies `pollWork` returns an error and reads at most `MaxPollResponseBytes + 1024` bytes.
   - `TestPollWork_MaxLegalAssignmentAccepted`: an assignment at `executor.MaxPayloadSizeBytes` (64 KiB) decodes completely.
   - `TestWorker_URLPathEscaping_RenewAndReport`: IDs containing `"../"`, `"?"`, `"#"`, and `"%2f"` reach the fake coordinator as single escaped path segments in both `renewOnce` and `reportResult`.
4. **Documentation**:
   - `docs/security/findings.md`: Updated SEC-060 and SEC-061 to Fixed (Slice P4-10).
   - `docs/PROJECT_STATE.md`: Moved SEC-060 and SEC-061 to Fixed findings.
   - `docs/agents/TASKS.md`: Added P4-10 task entry and updated active task table.
   - `docs/protocol.md`: Added sentence to section 6.2 stating that the worker bounds the poll response size and escapes path IDs.
   - Confirmed no line numbers in live documentation updates.
