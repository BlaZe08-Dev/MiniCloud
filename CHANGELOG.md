## [Unreleased]

### Added
- **Phase 3, Slice 3c — PostgreSQL Repository Implementation:**
  - `internal/storage/postgres`: Implemented `Repository` backed by `pgxpool.Pool` satisfying `storage.Repository`.
  - Mathematical deadlock prevention: Documented and enforced strict row locking order (`jobs` -> `workers` -> `attempts` -> `results` -> `job_events`) across all multi-table transactions.
  - Single-transaction atomic methods: Implemented `SubmitJob`, `DispatchJob`, `CommitAttempt`, and `CancelJob` mapping PostgreSQL SQLSTATE codes (`23505`, `23503`, `23514`) directly to typed domain errors.
  - Constant-time lease token verification: Computed SHA-256 hash in Go and compared stored hash in constant time (`crypto/subtle.ConstantTimeCompare`), preserving fine-grained typed errors (`ErrAttemptNotFound`, `ErrWorkerMismatch`, `ErrStaleAttempt`, `ErrJobAlreadyTerminal`).
  - Migration `000002_schema_hardening.sql`: Forward-only migration updating `idx_attempts_active_per_job` to cover non-terminal attempt states (`PENDING`, `RUNNING`) and replacing `worker_capacity` view to derive free slots from all active attempts.
  - Time & clock authority: Enforced database time via `make_interval(secs => $1::double precision)` in `ReapStaleWorkers` and `CURRENT_TIMESTAMP` in `RecordHeartbeat`. Added injectable `Clock` constructor option (`WithClock`) to `InMemoryRepository` for deterministic test time advancement.
  - Interface cleanup: Removed un-guarded generic mutations (`UpdateJob`, `CreateAttempt`, `UpdateAttempt`) from `storage.Repository` interface.
  - Shared conformance test suite: Added `internal/storage/conformance.go` exercising submit invariants, table-driven dispatch preconditions and precedence, commit validations, cancel transitions, worker reaping, and dynamic capacity derivation against both in-memory and PostgreSQL repositories.
  - Concurrency tests: Added `internal/storage/postgres/concurrency_test.go` with 50-goroutine start-barrier tests for same-job dispatch races, 1-slot worker capacity races, and duplicate commit races (`-race -count=50` clean).
  - Architecture boundary rules: Updated `tests/architecture/boundaries_test.go` asserting that `internal/domain`, `internal/coordinator`, and `internal/queue` never import `pgx` or `internal/storage/postgres`; verified failure on deliberate violation.
  - Dependency verification: Verified `pgxpool` dependency (`puddle/v2 v2.2.2`, `x/sync v0.8.0`) under `GOTOOLCHAIN=local go mod tidy` preserving `go 1.22.2` with zero toolchain directives; documented evidence in `docs/adr/0009-postgres-persistence-and-driver.md`.
- **Phase 3, Slice 3b — Database Provisioning, Schema & Forward-Only Migrations:**
  - `deployments/docker-compose.yml`: Pinned `postgres:16-alpine` service bound strictly to `127.0.0.1:5433` with named volume `minicloud_pgdata` and automated healthcheck.
  - `deployments/init-test-db.sh`: Initialized dedicated `minicloud_test` database alongside `minicloud` on clean container volume.
  - `.env.example` & `.gitignore`: Configured database secrets hygiene ensuring `.env` is never committed; documented host networking requirements.
  - `Makefile`: Added `@`-prefixed targets `db-up`, `db-down`, `db-psql`, `db-reset-test`, and `test-db`. Ensured zero volume removal (`db-down` retains volumes; `db-reset-test` drops only `minicloud_test` after asserting `_test` suffix).
  - `internal/domain`: Added `NewLeaseToken` (32 bytes entropy from `crypto/rand`, URL-safe base64) and `HashLeaseToken` (SHA-256 hex digest); verified 10,000 token uniqueness and Shannon entropy >= 32 bytes.
  - `internal/storage`: Updated `InMemoryRepository` to use domain lease token generation; hardened concurrent dispatch and commit tests with barrier synchronization (`-race -count=200` clean).
  - `internal/storage/postgres`: Implemented forward-only `Migrator` embedding migrations via `embed.FS`. Acquires `SELECT pg_advisory_xact_lock` FIRST inside transaction; creates `schema_migrations`; validates SHA-256 checksums to detect file tampering; executes unapplied migrations in version order. Unqualified SQL executes in caller's active `search_path`.
  - `internal/storage/postgres/migrations/000001_initial_schema.sql`: Initial schema migration creating `jobs` (`BYTEA` payload with `octet_length <= 65536`), `workers`, `attempts` (`TEXT` output with `octet_length <= 65536`, `TEXT` error with `octet_length <= 10240`), `results`, and `job_events` (`JSONB` details). Added partial unique index `idx_attempts_active_per_job` (`WHERE state = 'RUNNING'`) and `worker_capacity` view dynamically calculating available worker slots.
  - `cmd/migrate`: Added migration CLI binary for running migrations from terminal or scripts.
  - `internal/storage/postgres/migrator_test.go`: Added test suite running in isolated `test_<random_hex>` schemas dropped on cleanup with hard `_test` DB guardrail; verified fresh migration, idempotent re-run, checksum tampering detection (`ErrChecksumMismatch`), serialized concurrent runners (exactly one applies), and SQL schema invariant enforcement.
  - `tests/architecture/boundaries_test.go`: Extended architecture tests ensuring `internal/domain` and `internal/coordinator` never import `pgx` or `internal/storage/postgres`.
  - `docs/adr/0009-postgres-persistence-and-driver.md`: Recorded owner approval of `jackc/pgx/v5 v5.7.1` in Slice 3b with `GOTOOLCHAIN=local` guardrail and verified zero toolchain drift.
- **Phase 3, Slice 3a — Repository Atomicity Refactor & Worker Re-Registration:**
  - `internal/storage`: Introduced transaction-aligned atomic methods on `Repository` interface (`SubmitJob`, `DispatchJob`, `CommitAttempt`, and `CancelJob`) implemented with single-mutex atomicity in `InMemoryRepository`.
  - `internal/domain`: Added `AttemptOutcome` struct (ExitCode, Output, ErrorSummary, ErrorClassification) for atomic attempt completion.
  - `internal/domain`: Added `JobEvent` struct for recording lifecycle audit events alongside state mutations.
  - `internal/domain`: Added typed dispatch precondition errors (`ErrJobNotQueued`, `ErrWorkerNotFound`, `ErrWorkerNotHealthy`, `ErrTaskNotSupported`, `ErrWorkerNoCapacity`).
  - `internal/storage`: Implemented SHA-256 lease token hashing on attempt creation and constant-time verification (`crypto/subtle.ConstantTimeCompare`) on commit; raw lease token is returned to the worker strictly once on dispatch.
  - `internal/storage`: Dynamically derived worker `AvailableSlots` from active `RUNNING` attempts with zero stored mutable counter writes.
  - `internal/coordinator`: Integrated atomic storage methods into `SubmitJob`, `PollWork`, `CommitResult`, and `CancelJob`.
  - `internal/coordinator`: Handled queue claim outcomes deterministically (non-QUEUED or not found drops and acks; transient failure releases item; unhealthy/no capacity releases item without attempt creation).
  - `internal/coordinator`: Implemented honest `policy="fifo_pull"` and `reason="claimed by polling worker with capacity"` logging per ADR-0011 without calling `scheduler.SelectWorker`.
  - `internal/worker`: Added automatic client re-registration upon encountering HTTP 404 `WORKER_NOT_FOUND` during heartbeat and poll cycles.
  - `internal/worker`: Classified HTTP 404 attempt report rejections as non-retryable in `IsNonRetryableReportError` to allow workers to log and resume polling instead of looping indefinitely following an uncoordinated restart.
  - `tests/integration/coordinator_restart_test.go`: Added end-to-end integration test verifying worker survival, automatic re-registration, bounded handling of rejected in-flight reports, and resumed polling across coordinator restart.

  - `docs/adr/0010-migrations-policy.md`: Accepted Architecture Decision Record establishing forward-only schema migrations, expand/contract rules for destructive alterations, and an embedded in-tree runner with `pg_advisory_xact_lock` transaction advisory locking and SHA-256 checksum verification.
  - `docs/adr/0011-postgres-dispatch-and-recovery.md`: Accepted Architecture Decision Record defining PostgreSQL `SELECT ... FOR UPDATE SKIP LOCKED` pull dispatch (Option A), dynamic worker capacity derivation in SQL (no counter drift), surviving-worker restart recovery guarantees, SHA-256 hashed lease tokens, and accepting Candidate C (honest FIFO pull baseline, policy name `"fifo_pull"`) for Phase 3 dispatch. Dispatch logs record real facts only; `internal/scheduler` is intentionally unused in V1 dispatch; Candidate B rejected; Candidate A designated for post-Phase 4 "Assignment-Based Round-Robin" slice; hard gate recorded requiring scheduler-driven round-robin before V1 completion or V2 benchmarking.

- **Phase 2, Slice 2 — Dispatch-Transport Interface & 3-Worker Integration:**
  - `docs/adr/0008-dispatch-transport-queue-interface.md`: ADR defining the minimal queue interface, at-least-once delivery semantics, result-commit acknowledgement, and repository single source of truth invariant.
  - `docs/adr/0005-docker-isolation-in-v3.md`: Added "Known Gaps for V3 Container Executor" reviewing `internal/executor` against container requirements (cgroup limits, image mapping, stream handling).
  - `docs/protocol.md` & `docs/adr/0007-worker-liveness-and-recovery.md`: Documented Phase 2 correction distinguishing empty queue (HTTP 204 `NO_QUEUED_JOBS`) from unhealthy worker (HTTP 503 `WORKER_UNHEALTHY`).
  - `internal/domain`: Added `ErrWorkerUnhealthy` typed domain error.
  - `internal/api`: Mapped `ErrWorkerUnhealthy` to HTTP 503 `WORKER_UNHEALTHY`.
  - `internal/worker`: Handled HTTP 503 `WORKER_UNHEALTHY` in worker client, maintaining active heartbeats and polling without process termination.
  - `internal/queue`: Introduced `Queue` interface (`Enqueue`, `Claim`, `Release`, `Ack`, `Len`) and `Item` routing signal struct (`JobID`, `TaskType` only; payload and timeout read from repository at dispatch time).
  - `internal/queue`: Implemented thread-safe `InMemoryQueue` with FIFO ordering, capability matching, and in-flight delivery tracking.
  - `internal/coordinator`: Added `NewServiceWithQueue` constructor while keeping `NewService` signature defaulting to `InMemoryQueue`; integrated queue enqueue on submit, claim with repository state re-validation on poll (dropping non-QUEUED items and preventing duplicate attempts on redelivery), and queue ack strictly after accepted result commits.
  - `tests/architecture/boundaries_test.go`: Added boundary tests ensuring `internal/executor` does not depend on scheduler or queue, and `internal/queue` does not depend on api, coordinator, worker, or scheduler.
  - `tests/integration/multi_worker_batch_test.go`: Added 3-worker batch integration test executing 6 jobs across 3 independent worker processes, verifying parallel execution and distribution.
- **Phase 2, Slice 1 — Worker Liveness & Failure Recovery:**
  - `docs/adr/0007-worker-liveness-and-recovery.md`: Architecture Decision Record for worker liveness, atomic reaper loop, and failure recovery semantics.
  - `internal/storage`: Atomic `ReapStaleWorkers` and `RecordHeartbeat` methods in `InMemoryRepository` protecting against heartbeat/reap race conditions.
  - `internal/coordinator`: Background reaper loop `StartReaper` and `ReapInactiveWorkers` with injectable `Clock` abstraction for deterministic sub-millisecond testing.
  - `internal/coordinator`: Polling restriction excluding `UNHEALTHY` workers from claiming work; polling does not substitute for heartbeat telemetry.
  - `internal/coordinator`: Result commit acceptance for workers marked `UNHEALTHY` during execution for their valid attempt.
  - `internal/coordinator` & `internal/api`: Strict worker attempt ownership verification rejecting mismatched worker IDs with HTTP 403 `WORKER_MISMATCH`.
  - `internal/worker`: Permanent error classification via `IsNonRetryableReportError` treating HTTP 403 `WORKER_MISMATCH` and HTTP 409 conflict responses as non-retryable.
  - `internal/config`: Startup validation for configurable `MINICLOUD_REAPER_INTERVAL` (`> 0` and `<= MINICLOUD_WORKER_TIMEOUT`) and `MINICLOUD_WORKER_TIMEOUT >= 3 * MINICLOUD_HEARTBEAT_INTERVAL`.
  - `tests/integration/worker_liveness_test.go`: Automated integration test verifying dead worker reaping on SIGKILL, scheduler exclusion, and successful work routing to surviving workers.

- **Milestone 1 — Local Core:**
  - Go module initialized (`github.com/BlaZe08-Dev/Minicloud`) with zero third-party dependencies (stdlib only).
  - `internal/domain`: Pure domain model with Job, Attempt, and Worker entities; central FSM validation for all 9 states and typed `InvalidStateTransitionError`.
  - `internal/storage`: Thread-safe, non-durable `InMemoryRepository` with CRUD for jobs, attempts, and workers.
  - `internal/executor`: Allowlisted task execution registry with `echo`, `sleep` (bounded duration <= 10s), and `sha256_loop` (bounded iterations <= 1,000,000), context-driven timeout enforcement, 64 KiB payload limit, and 64 KiB output truncation.
  - `internal/scheduler`: Deterministic round-robin scheduler with candidate filtering (health, slots, supported tasks), deterministic tie-breaking, and structured decision logging.
  - `internal/coordinator`: Orchestration service implementing job submission, dispatching, and atomic result commitment with attempt ID and lease token verification for stale-result rejection.
  - `internal/api`: HTTP API server implementing endpoints (`POST /v1/jobs`, `GET /v1/jobs/{id}`, `GET /v1/jobs/{id}/attempts`, `POST /v1/jobs/{id}/cancel`, `GET /v1/workers`, `GET /healthz`, `GET /readyz`, `POST /v1/workers/register`, `POST /v1/workers/{id}/heartbeat`, `POST /v1/workers/{id}/poll`, `POST /v1/jobs/{id}/attempts/{attempt_id}/result`), request size limit (1 MiB), and structured JSON error envelope.
  - `internal/worker`: Independent worker agent communicating strictly via HTTP (registration, periodic heartbeats, pull/claim loop, execution, and result reporting).
  - `internal/config`: Environment variable configuration and startup validation.
  - `cmd/coordinator`, `cmd/worker`, `cmd/mc`: CLI application and daemons with structured `log/slog` output.
  - `Makefile`: Targets `build`, `test`, `test-race`, `fmt`, `vet`, `run-coordinator`, `run-worker`, `demo`.
  - Comprehensive test suite: Full 81-pair FSM transition matrix unit test, executor bounds test, scheduler determinism test, API validation and stale-rejection test, and multi-process integration test (`TestLocalCore_MultiProcessIntegration`).
  - Automated demo script `scripts/demo.sh`.
