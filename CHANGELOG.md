### Added
- **Phase 3, Slice 3d — PostgreSQL Coordinator Wiring, Durable Dispatch, Readiness Probe & Recovery:**
  - **Durable Dispatch (`repo.DispatchNextJob`):** Implemented single-transaction FIFO pull dispatch directly in PostgreSQL (`internal/storage/postgres/repository.go`) adhering to canonical deadlock-free lock order (`jobs` -> `workers` -> `attempts`). Employs unlocked worker pre-check preserving SEC-002 error precedence, candidate job selection via `SELECT ... FOR UPDATE SKIP LOCKED`, worker row locking with capacity re-check, and dynamic attempt number derivation (`COALESCE(MAX(attempt_no), 0) + 1`). Implemented in `InMemoryRepository` for shared conformance. Tested under extreme contention with `TestPostgresRepository_Concurrency_MixedOperationsStress` (`-race -count=20`) and `TestPostgresRepository_Concurrency_DispatchNextJob_StartBarrier` (`-race -count=50`).
  - **Coordinator Wiring & Queue Split:** Added `NewPostgresService` in `internal/coordinator/service.go`. In PostgreSQL mode, jobs bypass the in-memory queue entirely, preventing unbounded memory growth (SEC-010) and guaranteeing restart durability. In memory mode, the in-memory queue + `DispatchJob` path is preserved.
  - **Dynamic Boot-Time Schema Verification:** Configured `cmd/coordinator/main.go` to assert on startup that the active database schema version matches `migrator.LatestEmbeddedVersion()`, refusing to start on outdated schemas. Added `migrator.CurrentSchemaVersion`.
  - **Readiness Probe (`/readyz`) & Outage Resilience:** Updated `/readyz` endpoint in `internal/api/handlers.go` to verify repository reachability via `repo.Ping(ctx)`. Mapped connection failures and query timeouts to HTTP 503 `SERVICE_UNAVAILABLE` with `Retry-After: 1` and opaque body. Unmapped driver errors map to opaque HTTP 500 `INTERNAL_ERROR`.
  - **Worker Client Backoff & Outage Distinction:** Updated `internal/worker/client.go` implementing exponential backoff with full jitter on 5xx responses from `/poll` and `/heartbeat`, strictly distinguishing `SERVICE_UNAVAILABLE` (transient backoff) from `WORKER_UNHEALTHY` (wait for heartbeat restoration). Tested in `internal/worker/client_test.go`.
  - **Real-Process Crash Recovery & Outage Integration Tests:** Added `tests/integration/postgres_wiring_test.go` verifying: (1) coordinator restart mid-execution accepts surviving worker attempt report with HTTP 200 COMMITTED and dispatches surviving queued jobs; (2) database container outage returns 503 with `Retry-After: 1` on `/readyz` and job submission without leaking credentials, automatically recovering when the database restarts; (3) 50-job burst across 3 workers with mid-run coordinator kill completes all 50 jobs with zero loss or duplicates.
  - **Migration `000003_worker_limits.sql` & Check Constraint Defense:** Added migration enforcing `chk_workers_total_slots_range` ($1..1024$), `chk_workers_version_length` ($\le 64$), and `chk_workers_supported_tasks_count` ($\le 16$). Mapped check violations and SQLSTATE `22001`/`22003` to HTTP 400 `INVALID_REQUEST`.
  - **Worker Registration Limits (SEC-015, SEC-016, SEC-017):** Bounded `total_slots` to $1..1024$, `version` to $\le 64$ characters (empty allowed), `supported_tasks` to $\le 16$ items (empty allowed; each task name $1..64$ characters of `^[a-zA-Z0-9_-]+$`; unknown well-formed task names accepted for rolling fleet upgrades). Tested in `TestAPI_RegisterWorker_SlotsUpperLimit`, `TestAPI_RegisterWorker_VersionLengthLimit`, `TestAPI_RegisterWorker_SupportedTasksAllowlist`, `TestPostgresRepository_Security_WorkerCheckConstraints`, and `TestSchemaInvariants_SQLViolations`.
  - **Documentation & Specifications:** Created `docs/security/field-limits.md` specifying all field limits and database constraints, authored `docs/adr/0013-durable-dispatch-and-coordinator-recovery.md` detailing lock ordering and approximate FIFO trade-offs, and documented Phase 3 dead-worker limitation in `docs/failure-model.md`.
- **Phase 3, Slice 3d — Authorized Security Hardening (SEC-007, SEC-008, SEC-009, SEC-011, SEC-014):**
  - **SEC-007 (Internal Error Sanitization & Opaque HTTP 500):** Updated `internal/api/handlers.go` so unmapped storage or driver errors return a generic HTTP 500 `INTERNAL_ERROR` with an opaque message (`"internal server error"`). Server-side logging strips passwords and credentials (`password=***`). JSON decoder failures return a fixed `"malformed JSON request body"` message without leaking decoder internals or offsets. Verified by `TestAPI_UnmappedError_SimulatedDriverError_SanitizedInternalError500`, `TestAPI_UnmappedError_DatabaseOutage_SanitizedInternalError500`, and `TestAPI_SubmitJob_MalformedJSON_FixedMessage` (`internal/api/api_test.go:212-321`).
  - **SEC-008 (API Boundary Identifier Validation):** Implemented `isValidIdentifier` in `internal/api/handlers.go` enforcing length bounds ($\le 128$ characters) and strict character set `^[a-zA-Z0-9_-]+$` across worker registration (`worker.ID`), query parameters (`{id}`, `{attempt_id}`), and commit requests (`req.WorkerID`). Verified with negative tests (100 KiB ID, control characters, newlines, path traversal `../../`, SQL characters) in `TestAPI_IdentifierValidation_NegativeCases` (`internal/api/api_test.go:323-412`).
  - **SEC-009 (Explicit HTTP Server ReadHeaderTimeout):** Added `DefaultReadHeaderTimeout = 2 * time.Second` to `internal/api/server.go` on `http.Server`, mitigating Slowloris connection pool exhaustion. Added `Serve(ln net.Listener)` method. Verified by `TestAPI_Slowloris_ReadHeaderTimeout` (`internal/api/api_test.go:414-473`).
  - **SEC-011 (Migration CLI Credential Exposure Deprecation):** Updated `cmd/migrate/main.go` to prioritize `MINICLOUD_DATABASE_URL` environment variable. If the `-database-url` flag is passed, emitted a deprecation warning explaining that CLI flags expose connection strings and credentials in the system process table (`ps aux`, `/proc`). Verified by unit tests in `cmd/migrate/main_test.go:8-61`.
  - **SEC-014 (Numeric Parameters Boundary Validation):** Updated `internal/api/handlers.go` (`SubmitJobRequest`) and `internal/coordinator/service.go` (`SubmitJob`) to enforce boundary limits on `max_attempts` ($1..20$, default 3 when omitted or null) and `timeout_seconds` ($1..86400$, default 60 when omitted or null) returning HTTP 400 `INVALID_REQUEST`. Mapped PostgreSQL check constraint violations (`chk_jobs_max_attempts` and `chk_jobs_timeout` under SQLSTATE `23514`) directly to typed `domain.ErrInvalidRequest` so check violations always map to HTTP 400 client errors and never to opaque 500 internal server errors. Verified by `TestAPI_SubmitJob_BoundaryValues`, `TestAPI_PostgresCheckConstraint_MapsToClientErrorNever500` (`internal/api/api_test.go:476-608`), and `TestPostgresRepository_Security_CheckConstraints_NumericBounds` (`internal/storage/postgres/security_test.go:809-883`).

- **Phase 3, Slice 3c — PostgreSQL Repository Implementation & Review Hardening:**
  - `internal/storage/postgres`: Implemented `Repository` backed by `pgxpool.Pool` satisfying `storage.Repository`.
  - Mathematical deadlock prevention: Documented and enforced strict row locking order (`jobs` -> `workers` -> `attempts` -> `results` -> `job_events`) across all multi-table transactions. Empirically verified under extreme contention by `TestPostgresRepository_Concurrency_MixedOperationsStress` (60 goroutines, start barrier, overlapping jobs/workers, `-race -count=20`).
  - Single-transaction atomic methods: Implemented `SubmitJob`, `DispatchJob`, `CommitAttempt`, and `CancelJob` mapping PostgreSQL SQLSTATE codes (`23505`, `23503`, `23514`) directly to typed domain errors.
  - Constant-time lease token verification: Computed SHA-256 hash in Go and compared stored hash in constant time (`crypto/subtle.ConstantTimeCompare`), preserving fine-grained typed errors (`ErrAttemptNotFound`, `ErrWorkerMismatch`, `ErrStaleAttempt`, `ErrJobAlreadyTerminal`).
  - Worker mismatch logging attribution fix: Introduced `domain.WorkerMismatchError` to carry both `AssignedWorker` and `ReportingWorker`. `CommitAttempt` in both repositories populates this struct. The coordinator logs the true assigned worker and reporting worker, never logs lease tokens, and the client-facing HTTP 403 API response continues to obscure the assigned worker ID.
  - Conformance helper refactor: Moved conformance test suite to separate non-production helper package `internal/storage/storagetest` so `internal/storage` contains zero imports of `"testing"`.
  - Migration `000002_schema_hardening.sql`: Forward-only migration updating `idx_attempts_active_per_job` to cover non-terminal attempt states (`PENDING`, `RUNNING`) and replacing `worker_capacity` view to derive free slots from all active attempts. Tested both second-RUNNING and second-PENDING invariant rejections.
  - Time & clock authority: Enforced database time via `make_interval(secs => $1::double precision)` in `ReapStaleWorkers` and `CURRENT_TIMESTAMP` in `RecordHeartbeat`. Added injectable `Clock` constructor option (`WithClock`) to `InMemoryRepository` for deterministic test time advancement.
  - Security review suite: Added `internal/storage/postgres/security_test.go` verifying immunity against SQL injection across all fields, exact payload/output boundary limits ($65535, 65536, 65537$ bytes), forged token rejection, commit replay resistance, mid-transaction context cancellation atomicity, and an AST static analysis checker (`CheckSQLSafety`). The checker inspects all `Exec`, `Query`, `QueryRow`, and `Queue` invocations across all non-test `.go` files in `internal/storage/postgres` (`migrator.go`, `repository.go`), asserting query arguments are string literals, declared constants, or variables whose every assignment in the file is a string literal (rejecting `fmt.Sprintf`, `+` string concatenation, function calls, and function parameters; verified on positive and negative test fixtures). A single narrow allowlist is granted to `migrator.go`'s `Migrate` method executing `migration.Content` (embedded build-time SQL, checksummed, not caller-controlled). Limitation: single-file AST inspection does not detect dynamic SQL assembled in external helper functions returned as strings.
  - Concurrency tests: Added `internal/storage/postgres/concurrency_test.go` with 50-goroutine start-barrier tests for same-job dispatch races, 1-slot worker capacity races, duplicate commit races (`-race -count=50` clean), and mixed-operations stress testing (`-race -count=20` clean).
  - Architecture boundary rules: Updated `tests/architecture/boundaries_test.go` asserting that `internal/domain`, `internal/coordinator`, and `internal/queue` never import `pgx` or `internal/storage/postgres`; verified failure on deliberate violation.
  - Dependency verification: Verified `pgxpool` dependency (`puddle/v2 v2.2.2`, `x/sync v0.8.0`) under `GOTOOLCHAIN=local go mod tidy` preserving `go 1.22.2` with zero toolchain directives; documented evidence in `docs/adr/0009-postgres-persistence-and-driver.md`.
